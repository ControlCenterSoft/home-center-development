## Purpose

The read-only reconciliation runtime can already persist exact `verified` evidence, but
it deliberately keeps the original protected Desired State in
`enforcement_verified=false / reconciliation_required=true`.

This slice adds the next protected local transition boundary without changing that
original Desired State object. It persists an immutable **verified Desired State
projection** that is content-bound to:

- exact Household/member;
- Desired State generation, originating plan, policy identity and policy digest;
- full source Desired State SHA-256;
- reconciliation request/backend identity;
- immutable reconciliation evidence identity and SHA-256;
- exact observation timestamp.

The verified projection can exist only when completed durable reconciliation evidence
is exactly `verified`, the observed policy digest equals the requested policy digest,
all mutation/publication flags are false, the current Desired State still matches the
pre-observation SHA-256, and the caller is still an enabled parent/administrator.

## Fail-closed transition

`HouseholdPolicyVerificationStateService.transition()` performs:

1. strict request/evidence identifier validation before store lookup;
2. completed reconciliation envelope/request/evidence revalidation;
3. current Household parent/admin authority revalidation;
4. exact current protected Desired State re-read and SHA-256/binding validation;
5. durable transition-state + Job creation;
6. verified projection persistence;
7. exact StateStore read-back;
8. Job evidence, transition receipt and Audit persistence.

The transition is restart-safe around the projection write. Replaying the same exact
transition resumes the existing Job/transition state and does not call a backend.
Conflicting same-generation verification material, stale Desired State, non-verified
evidence, malformed identifiers and stale generation replacement all fail closed.

A newer Desired State generation may replace an older verified projection only after
its own exact reconciliation evidence qualifies.

## Deliberate safety boundary

This slice does **not**:

- call, execute or mutate a policy backend;
- mutate the source protected Desired State object;
- authorize infrastructure/network/filesystem changes;
- authorize external publication;
- expose a new HTTP route;
- accept credentials/endpoints/arbitrary commands;
- claim that a production policy backend exists;
- grant RC/Stable or commercial/legal clearance.

The source Desired State remains immutable evidence of what was requested. The verified
projection is a separate exact-bound Actual State proof. A later API/effective-state
layer may consume this projection only behind the existing authentication,
same-origin/CSRF, scoped re-auth, Household RBAC and idempotency fences.

## Qualification added by this slice

Focused regressions cover:

- successful exact verified projection persistence;
- idempotent replay with no backend reinvocation;
- rejection of pending/non-verified reconciliation;
- current parent/admin authority revalidation;
- stale/tampered Desired State rejection;
- hostile request/evidence identifiers;
- interruption after projection write and restart-safe completion;
- StateStore backup/restore preservation;
- Draft 2020-12 contract validation.

Only normal PR-triggered hosted qualification is intended. No workflow dispatch,
synthetic load, cancellation or unchanged rerun is required.
