# Home Center 0.61 — VPN egress policy foundation

Status: development architecture; not Release Candidate and not Public Stable.

## Architecture

The 0.61 model is provider-neutral and side-effect free. A VPN egress policy is bound to an exact composed Household policy and, when parental filtering is active, to the exact parental Internet policy identity used for the decision. Provider evidence is bound to provider/version/location plus reachability, latency, stability, supported DNS strategies, split-routing support, kill-switch support and an evidence digest.

The current Household role presets remain authoritative. A VPN policy must never turn `vpn_allowed=false` into true and therefore cannot weaken Policy Composer anti-escalation rules.

DNS strategy is explicit: `provider`, `parental` or `system`. `system` is rejected whenever it could bypass filtering. A parental-bound policy requires controlled DNS, kill switch enabled and deny fallback.

Kill-switch and fallback semantics cannot contradict each other: kill switch requires deny fallback. Provider evidence that is unreachable or outside configured latency/stability thresholds therefore fails closed when kill switch is active.

Split routing uses a bounded normalized domain set. Matching domains select VPN; non-matching domains may select direct egress only when the policy explicitly permits direct fallback. Missing, malformed or ambiguous routing input fails closed.

A bound parental Internet decision is evaluated before route selection. `DENY` always stops both VPN and direct egress. VPN therefore cannot override a stricter parental result.

Provider selection, observation and route decisions are evidence only. They carry no execution, infrastructure-mutation or external-publication authority. Active VPN state requires a later typed execution boundary plus exact post-condition read-back and verification.

## Persistence and recovery boundary

The policy identity is content-addressed from exact Household/member/base-policy/provider evidence and routing settings. Persisted representations must be reconstructed strictly: unknown fields, mismatched digests, invalid authority flags, stale provider evidence and contradictory kill-switch/fallback values are rejected fail-closed.

A future execution layer must persist a pre-mutation recovery snapshot before any provider/network mutation, must never retry an ambiguous provider outcome automatically, and must be able to reconcile state read-only after restart without repeating the mutation.

## User interface

`Уютный` should explain outcomes in household language: VPN selected, safe block because VPN is unavailable, parental rule blocked access, or split routing selected direct egress. It must not expose an unavailable provider as working and must not describe provider command acceptance as successful VPN activation.

`Полный` may additionally expose provider/location, latency and stability thresholds, DNS strategy, split-routing rules, kill-switch/fallback mode and evidence identities.

## Security boundary

- parental DENY has absolute precedence;
- exact policy/provider evidence is mandatory;
- secret values and credentials are not part of policy/evidence contracts;
- no generic shell or arbitrary routing command is exposed;
- execution, infrastructure mutation and external publication remain false in this foundation;
- unknown/stale/ambiguous state is never rendered as active or healthy.
