# Home Center 0.61 — VPN egress policy foundation

Status: development architecture; not Release Candidate and not Public Stable.

Public Stable at preparation time is 0.58.0, so the active development boundary is 0.59–0.61. This work is stacked on the prepared 0.60 parental Internet policy line and contains no 0.62+ scope.

## Architecture

The 0.61 model is provider-neutral and side-effect free. A policy binds to an exact 0.59 composed Household policy and, when present, an exact 0.60 parental policy identity. Provider evidence is bound to provider/version/location plus reachability, latency, stability, supported DNS strategies, split-routing support, kill-switch support and an evidence digest.

The current Household role presets remain authoritative. 0.61 never turns `vpn_allowed=false` into true. This preserves the anti-escalation rule already enforced by Policy Composer.

DNS strategy is explicit: `provider`, `parental` or `system`. `system` is rejected for filtered policy. A parental-bound policy requires controlled DNS, kill switch enabled and deny fallback.

Kill-switch and fallback semantics cannot contradict each other: kill switch requires deny fallback. Current provider evidence that is unreachable or outside latency/stability thresholds therefore fails closed when kill switch is active.

Split routing uses a bounded normalized domain set. A matching domain selects VPN, a non-matching domain selects direct egress, and missing or invalid routing input fails closed when split routing is required.

A bound parental Internet decision is evaluated before route selection. DENY always stops both VPN and direct egress. VPN therefore cannot override a stricter parental result.

Provider selection and route decisions are evidence only. They carry no execution, infrastructure-mutation or external-publication authority. Active-state claims require a later typed execution and post-condition verification boundary.

## User interface

«Уютный» should explain outcomes in household language: VPN selected, safe block because VPN is unavailable, parental rule blocked access, or split routing selected direct egress. «Полный» may additionally expose provider/location, thresholds, DNS strategy and evidence identities.
