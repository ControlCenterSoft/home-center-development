# Home Center 0.58 — bounded failed-enrollment cleanup execution

Status: development runtime slice; **not Release Candidate and not Public Stable**.

This layer closes the local execution half of the failed-enrollment cleanup path after the existing
read-only provider verification has explicitly authorized transient cleanup. It does not add any new
provider capability and does not weaken the 0.57/0.58 fail-closed boundaries.

## Authority chain

Cleanup execution requires the exact existing chain:

`rejected NR1 verification -> deterministic cleanup plan -> current Household/RBAC revalidation -> read-only provider read-back -> authorized cleanup receipt -> explicit execute confirmation -> durable Job -> bounded local deletion -> local read-back -> Audit/evidence`.

The execute boundary refuses blocked/stale/mismatched cleanup state and revalidates the current
Household snapshot/bindings before creating a mutation Job. The provider is **never called** by this
layer.

## Bounded mutation

The only permitted mutation is clearing `one_time_artifact` from the exact persisted 0.57 enrollment
execution receipt when that artifact is a validated single-use `secret://` reference. The reference
value is never copied into Job/Audit/evidence; only a SHA-256 digest may be retained as deletion
evidence.

The immutable enrollment execution plan is preserved, including its credential references. Those
references are audit inputs and are not credential values. The cleanup executor does not remove or
rewrite the execution plan.

The boundary explicitly cannot:

- invoke provider enrollment/de-enrollment/cancel operations;
- change `ManagedDevice.managed` or any Household device/member record;
- mutate policy, device records, infrastructure, network/publication state or credentials;
- treat cleanup authorization as enrollment/de-enrollment success.

If the original provider execution requested no one-time artifact, cleanup may complete with
`one_time_reference_removed=false`; this is not reported as a deletion that did not occur.

## Durability and replay

A durable mutation intent is persisted before the reference is cleared. Replaying the same
idempotency key resumes or returns the same Job rather than creating a second cleanup. If a process
stops after local deletion but before Job completion, the verifying state can finish from local
read-back without any provider mutation.

The final receipt records the exact cleanup/enrollment plan bindings, cleanup generation, sanitized
execution-state digest and negative authority flags. The Household state is read-only throughout this
slice.

## Remaining gates

This slice does not qualify a concrete production provider adapter/verifier, does not add public API
routing by itself, and does not replace real target-node or multi-node HA/restart acceptance.
Commercial/legal clearance is not claimed. Public Stable remains 0.56.0; PR #158 remains the nearest
0.57 release-candidate path and its remaining gates are real-environment/provider gates.
