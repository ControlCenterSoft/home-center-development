# Home Center 0.59 — effective policy read model for «Уютный» and Full UI

Status: **non-runner source slice; read-only projection only; no production authority**.

Base source: `39fe16ba450dbc5b2709a77889877bb89cadae5d` (Draft PR #173 exact head).
Public Stable remains 0.56.0. The allowed development horizon for this work is 0.57.0–0.59.0 only.

## Purpose

Policy Composer now has three distinct durable layers:

1. protected Desired State (`enforcement_verified=false`, `reconciliation_required=true`);
2. read-only reconciliation evidence from an exact policy backend;
3. a protected verified-state projection bound to the exact Desired State and evidence.

The next missing product-facing layer is a **safe read model**. The UI must not infer success from
the existence of a policy, a completed Job, or stale historical verification. This slice adds one
read-only projection that both «Уютный» and the Full UI can consume later through the existing
authenticated API boundary.

## States

The projection has only three user-facing states:

- `role-default` — no Policy Composer Desired State exists; the fixed Household role preset is shown;
- `pending-reconciliation` — a composed Desired State exists but there is no exact current verified
  evidence for that generation;
- `verified` — the current Desired State is exactly bound to the durable verified-state projection
  and the original reconciliation evidence is still present and internally consistent.

A verified projection from an older Desired State generation is never reused for a newer generation.
A future-generation projection, orphan projection, malformed Desired State, tampered verification
projection, or missing/mismatched durable evidence fails closed.

## Authorization

The read model uses server-side Household actor bindings only:

- a member may read their own effective policy state;
- another member's state may be read only by an enabled parent with administration capability;
- disabled or unbound actors fail closed.

No authority is taken from the client request.

## Output boundary

The read model returns a bounded technical policy plus the simple Russian explanation used by
«Уютный». It never exposes secret values, arbitrary backend payloads, credentials, endpoints, or
commands. Verified evidence is reduced to identifiers, digest and observation time.

Every result keeps:

- `infrastructure_mutation_authorized=false`;
- `external_publication_authorized=false`;
- `production_mutation_enabled=false`.

The read operation creates no Job, performs no Audit mutation, invokes no backend, changes no Desired
State, and does not grant RC/Stable/commercial/legal clearance.

## Integration order

This source slice is intentionally not exposed through HTTP yet. A later integration pass may wire
it into the existing authenticated API only after preserving the current same-origin/CSRF, RBAC and
session/re-auth boundaries. «Уютный» and Full UI must consume the same read model and must not create
a parallel execution path.

## Release priority

This 0.59 work does not supersede the 0.57 release lane. The remaining 0.57 gates are still real
target-node acceptance, multi-node HA/restart acceptance, qualification of a concrete provider
adapter and approved exact-candidate commercial/legal Production evidence. The 0.58 stacked line
also remains ahead of 0.59 in release order.
