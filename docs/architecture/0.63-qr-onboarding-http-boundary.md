# Home Center 0.63 — QR onboarding authenticated HTTP boundary

The 0.63 QR invitation state machine is exposed through four bounded POST routes:
`issue`, `plan`, `consume` and `revoke`. The handler extends the current V9 HTTP
chain and reuses the existing request-classification, external-access, authenticated
session and same-origin/CSRF fences. Request bodies remain bounded to 8192 bytes and
all QR request objects are parsed by the existing closed transport-neutral schemas.

Server time is authoritative. The client cannot choose the issuer actor: issue and
revoke resolve the authenticated actor through the current Household actor binding.
Consume keeps the authenticated actor only as the idempotency/Audit principal and
still requires the single-use onboarding code and exact redemption plan. The QR
runtime is wrapped by the receipt-only StateStore Audit boundary so successful
mutations append privacy-minimized evidence without persisting the raw code or QR
payload.

This HTTP layer does not turn invitation consumption into onboarding success.
Account creation, device registration/binding, `managed=true`, provider execution,
infrastructure mutation and external publication remain outside this boundary and
unauthorized. The later typed Change/Job effect and its post-condition verification
remain separate mandatory 0.63 gates.

The handler module is qualified independently before it becomes the canonical server
handler. Production handler selection/composition and canonical QR schema migration
remain separate integration gates. Public Stable remains 0.62.1.
