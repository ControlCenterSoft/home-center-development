# Home Center 0.66 — Smart Home device lifecycle foundation

## Граница версии

0.66 продолжает 0.65 ZigBee/MQTT foundation и подготавливает продуктовый слой жизненного цикла устройств для «Мой дом». Этот slice является plan/read-only foundation: он не выполняет pairing/unpairing, provider command, rename/move mutation, network/infrastructure change, external publication или HA/failover.

## Источники истины

Read model связывает два независимых источника:

- freshness-bound inventory snapshot 0.65 с exact `inventory_sha256`, фактическими capabilities, room observation, battery/link evidence;
- локальный Home Center profile с `device_id`, monotonic `generation`, понятным именем и назначенной комнатой.

Stale/Unavailable evidence не превращается в Healthy и не используется для change plan. Room drift вычисляется только по current/current evidence; при stale/unknown состоянии расхождение комнаты не выдумывается.

## Health и diagnostics

Базовые состояния: `healthy`, `degraded`, `stale`, `unknown`. Bounded diagnostics: low battery, weak link, room drift, stale evidence, unavailable evidence. Capability mapping детерминированно сворачивает технические capabilities в бытовые семейства lighting/switch/sensor/climate/security/cover/media/other.

«Уютный» показывает имя, комнату, бытовой статус и семейства возможностей без coordinator/provider/transport details. «Полный» получает exact inventory/profile evidence, diagnostics и drift.

## Rename / move-room planning

Rename и move-room создают только content-addressed plan, привязанный к exact `inventory_sha256` и текущему `profile_generation`. План содержит before/target metadata, требует explicit confirmation и recovery snapshot. No-op, stale inventory, stale device evidence и попытка смешать поля разных операций отклоняются fail-closed.

Положительный plan не выдаёт `execution_authorized`, `provider_execution_authorized`, `device_state_mutation_authorized`, `infrastructure_mutation_authorized` или `external_publication_authorized`.

## Следующий слой

До runtime mutation нужны отдельные authenticated Household/RBAC boundaries, durable Change/Job, optimistic generation CAS, Audit, post-condition read-back и recovery. Pair/unpair остаются в отдельном 0.65 operation lifecycle и не должны маскироваться обычным rename/move flow. HA не заявляется: физический single coordinator из 0.65 остаётся честным ограничением.
