# Home Center 0.60 — Parental Internet/DNS/Proxy policy foundation

Status: runner-free development foundation; **not Release Candidate and not Public Stable**.

Canonical Public Stable is 0.57.0. Under the current three-release development boundary, 0.60 is the furthest permitted release. This slice is stacked on the qualified 0.59 policy line and does not implement any 0.61+ capability.

## Scope

The foundation introduces a deterministic policy model for a child member only. It binds policy decisions to:

- exact Household/member and the exact composed 0.59 base policy identity;
- a content-addressed rule source (`rule_source_id`, version and SHA-256);
- explicit domain allow/deny lists;
- explicit category allow/deny lists;
- bounded weekly schedule windows;
- daily and weekly usage quotas;
- continuous-session limit, grace window, mandatory break and bounded daily bonus.

The model is intentionally side-effect free. It does not configure DNS, proxy, firewall, routing, VPN, browser settings or a client device.

## Fail-closed precedence

Decision order is deterministic and designed so an allow rule cannot bypass parental time controls:

1. exact policy/Household/member binding;
2. exact rule-source version and SHA-256 binding;
3. explicit domain deny;
4. allowed schedule;
5. weekly quota;
6. daily quota including bounded bonus;
7. continuous-session limit including bounded grace and required break;
8. explicit domain allow;
9. category deny / allow;
10. missing classification or unknown allow-list membership => DENY.

For child policy, an unavailable classification is not interpreted as safe access. Stale or mismatched rule-source evidence is always DENY.

## Safety and authority boundary

Every policy and decision explicitly keeps:

- `enforcement_authorized=false`;
- `infrastructure_mutation_authorized=false`;
- `external_publication_authorized=false`.

`dns_policy_required=true` and `proxy_policy_required=true` are requirements for a future typed enforcement adapter, not claims that enforcement happened. A later 0.60 slice must introduce an adapter capability contract, Desired/Actual State, post-condition verification and recovery before Home Center may claim the policy is enforced.

VPN is not implemented here. The existing child role keeps `vpn_allowed=false`; 0.61 VPN egress remains outside the current implementation and must never override a stricter parental DENY.

## UI semantics

The future Cozy projection must explain the decision in household language (for example: blocked by schedule, quota exhausted, category blocked, source unavailable) without exposing provider internals. Full UI may show exact rule-source identity, schedule/quota values and reason code. Neither view may show a false success or claim that DNS/proxy enforcement is active before Actual State verification.

## Qualification boundary

This branch intentionally has no PR and its branch name is outside `main` and `release/**`; repository push workflows therefore do not run for these commits. Test and contract code is prepared for the next runner-qualified integration pass, but no runner/check/workflow is launched by this non-runner stream.
