# Home Center 0.58 — post-condition verification contract

Status: development contract slice; **not Release Candidate and not Public Stable**.

This layer defines a provider-neutral, fail-closed contract for proving that a provider-backed
device enrollment actually reached its expected post-condition. It is stacked on the Home Center
0.57 enrollment-execution boundary and does not weaken any 0.57 safety gate.

## Safety model

A provider accepting an enrollment command is not proof that the device is managed. Verification
must bind exactly to the execution plan, provider operation, device, member and execution
generation, and it must be based on an explicit provider read-back.

The contract permits `managed_state_change_authorized=true` only in a `verified` verification
receipt. Rejected verification is fail-closed: enrollment remains incomplete, managed state is not
authorized, and cleanup is required.

Secret values are outside this contract. The verification layer contains no credential material,
does not authorize policy application, infrastructure mutation or external publication, and does
not register a concrete provider verifier.

## Evidence

Verification results expose bounded certificate/profile/agent signals. Evidence is content-addressed
with SHA-256 and records either a successful verification or a bounded failure reason. Closed JSON
Schemas reject extra fields to prevent accidental authority or secret expansion.

## Remaining work

Before 0.58 can be considered for RC, runtime integration still needs durable verification-job
execution/recovery, a concrete production provider verifier and its qualification, explicit
de-enrollment and cleanup/recovery workflows, plus full release/install/upgrade qualification.
Commercial clearance is not claimed by this contract slice.
