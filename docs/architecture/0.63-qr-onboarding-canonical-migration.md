# Home Center 0.63 — canonical QR StateStore migration

QR onboarding durable state is installed through the existing versioned `StateStore` migration sequence. Migration 4 adds only the prepared `qr_onboarding_runtime` and `qr_onboarding_runtime_operations` tables. The SQL is kept byte-for-byte equivalent to `SQLiteQrOnboardingRuntimeRepository.schema_sql()` so the repository adapter remains schema-compatible while continuing to refuse self-migration.

The migration is additive. Existing migrations 1–3 remain unchanged, and upgrading an existing v3 state database preserves prior metadata, Jobs, Audit, Desired State and Home Service state. A fresh StateStore and a v3→v4 upgrade both install the QR schema before the QR repository is constructed.

This slice closes canonical QR schema installation only. It does not register authenticated HTTP routes, authorize the later guest/device effect, create accounts or devices, change managed state, execute a provider, mutate infrastructure or authorize external publication. StateStore Audit wiring is a separate qualified boundary, and onboarding effect success remains false until the later typed Change/Job and post-condition verification gates are complete.
