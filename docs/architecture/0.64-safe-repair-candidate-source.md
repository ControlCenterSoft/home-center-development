# Home Center 0.64: источник кандидатов safe-repair из состояния сервера

Статус: runner-free подготовка; не является полномочием на выпуск.

Источник принимает только типизированное read-only наблюдение, сформированное из
производного состояния, которым владеет Home Center. Закрытый набор источников
содержит канонический производный индекс StateStore и локальную read model.
Состояние provider, произвольный shell-вывод, внешняя публикация и утверждения
клиента не могут быть подставлены как альтернативный источник.

Наблюдения `current` и `unknown` не создают кандидата на исправление. Наблюдение
`stale` обязано содержать различающиеся фактический и ожидаемый content digest;
наблюдение `missing` не должно заявлять фактический digest. Противоречивые
наблюдения отклоняются fail-closed.

Для `stale` или `missing` источник формирует exact-bound `RepairCandidate` с
authoritative Household/resource identity, generation ресурса и SHA-256 полного
наблюдения. Действие жёстко определяется типизированным источником:

- производный индекс StateStore → `rebuild-derived-index`;
- локальная read model StateStore → `refresh-local-read-model`.

Оба действия остаются локальными low-risk операциями над производным состоянием
продукта. Источник не выдаёт execution, credential, provider, generic
infrastructure или external-publication authority, ничего не изменяет и не
регистрирует adapter.

Recovery нельзя выводить только из наличия drift. Если проверяемое recovery
evidence отсутствует, кандидат получает `recovery_proven=false`, и существующий
eligibility evaluator блокирует автоматическое исправление. Следующий runtime
slice всё равно обязан выполнить authenticated/RBAC admission, свежее exact-state
revalidation, создание durable Job, отдельную регистрацию typed adapter,
authoritative post-condition read-back, сохранение Audit/recovery evidence и
историю UI без false success.
