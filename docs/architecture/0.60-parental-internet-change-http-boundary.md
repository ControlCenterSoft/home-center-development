# Home Center 0.60 — protected parental Internet change HTTP boundary

## Scope

This boundary exposes the existing 0.60 parental Internet Desired State workflow through the authenticated Home Center web runtime while preserving the common mutation discipline:

`session → Household parent authority → exact plan → scoped credential re-auth → explicit confirmation → durable Job → protected Desired State write → read-back → Audit/evidence`.

It does not execute DNS, proxy, firewall, routing or external-publication changes. A successful confirmation means only that the parental Desired State was saved and read back.

## HTTP lifecycle

### Plan

`POST /api/v1/household/parental-internet/plan`

The request uses the existing closed `parental-internet-policy-plan-request.v1` contract. The HTTP body is bounded to 256 KiB because the already-defined rule contract can contain bounded domain/category lists and schedule entries that legitimately exceed the small control-message limit.

The route is authenticated, same-origin, external-access filtered and parent-authorized. The service binds the proposal to:

- exact Household snapshot/resource version/generation;
- authenticated parent binding;
- child subject identity;
- exact verified 0.59 policy state and evidence;
- current parental Desired State generation/digest;
- exact rule-source id/version/SHA-256;
- proposed parental policy digest.

A plan does not authorize a write or provider execution.

### Scoped re-authentication

`POST /api/v1/household/parental-internet/reauth`

The request carries only provider, username, password and exact `plan_id`. The client cannot choose a raw step-up scope. Before credentials are accepted for a grant, the service revalidates the immutable plan, current parent authority, Household snapshot, child eligibility and exact verified 0.59 base. A stale or foreign plan cannot receive a grant.

The resulting scope is derived server-side:

`household.parental-internet.policy:<plan_id>`

The grant is short-lived, in-memory, actor-bound, exact-plan-bound and single-use. Restart/failover discards unused grants and therefore fails closed. Passwords and grants are not written to StateStore, Job evidence or Audit details.

Rate limiting is independent from normal login and existing generic re-auth traffic.

### Confirm

`POST /api/v1/household/parental-internet/confirm`

The request must include:

- closed confirm body with `confirmed=true`;
- `Idempotency-Key` exactly equal to the `plan_id`;
- `X-Home-Center-Step-Up` containing the exact single-use grant.

Before consuming the grant, the safe wrapper performs a read-only plan/current-state preflight. After the grant is consumed, the base runtime repeats all exact-state checks under its own lock before any durable mutation. A race between the preflight and the write therefore causes the base runtime to fail closed rather than using the consumed grant as authority for a changed state.

An already committed exact request is an idempotent receipt read: current parent authority and receipt/plan binding are revalidated, but a new credential grant is not required and no second Job is created.

## False-success boundary

The existing commit receipt remains hard bounded:

- `enforcement_verified=false`;
- `reconciliation_required=true`;
- `dns_policy_applied=false`;
- `proxy_policy_applied=false`;
- `infrastructure_mutation_performed=false`;
- `external_publication_performed=false`.

No route in this boundary registers or invokes a DNS/proxy provider adapter. Concrete enforcement and read-back verification remain separate 0.60 work and must use the typed adapter/reconciliation contracts already present in source.

## Security properties

- arbitrary client-selected step-up scopes are rejected by design;
- foreign actor/plan combinations fail before credential grant or mutation;
- stale Household or verified-base evidence fails closed;
- credential values and step-up tokens never enter persistent evidence;
- cross-origin POSTs are rejected by the inherited Home Center origin fence;
- plan/confirm/re-auth are unavailable through the external publication boundary;
- no generic command/shell or infrastructure mutation authority is introduced.

## Release boundary

`parental_internet_policy_runtime_safe.py` is a required release-wheel member. This work is source-prepared only until a runner-enabled release flow qualifies the exact head. It does not change the canonical Stable version and does not claim Home Center 0.60 RC/Public Stable readiness.
