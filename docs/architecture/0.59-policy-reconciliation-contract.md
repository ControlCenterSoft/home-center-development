# Home Center 0.59 — typed policy reconciliation boundary

Status: source-level preparation for the 0.59 Policy Composer track. This boundary is intentionally non-production and does not grant enforcement authority.

## Purpose

The protected household policy Desired State is already durable, fail-closed and marked `reconciliation_required=true`. The missing boundary is a typed hand-off from that exact Desired State to a concrete provider adapter and back to an auditable Actual State observation.

This change introduces three closed contracts:

- `household-policy-reconciliation-request.v1` — binds household/member, Desired State generation, plan, policy hash, adapter revision and target;
- `household-policy-reconciliation-observation.v1` — binds the provider read-back to the exact request and carries Actual State/evidence hashes plus the provider receipt;
- `household-policy-reconciliation-decision.v1` — records a side-effect-free reconciliation decision.

## Safety model

The reconciliation code is pure and side-effect free. It does not call a provider, write Desired State, mutate infrastructure, publish anything externally, or change `enforcement_verified`.

A `verified` observation becomes only `verified_candidate` when all exact bindings match, the observed policy hash equals the Desired State policy hash, and a provider receipt is present. Even then the decision deliberately retains:

- `enforcement_verified=false`;
- `reconciliation_required=true`;
- `infrastructure_mutation_authorized=false`;
- `external_publication_authorized=false`.

A later durable writer may consume this typed evidence only after a concrete provider adapter is qualified and the release/commercial gates allow that capability. The writer must revalidate the current Desired State and adapter trust before changing any authoritative state.

## Fail-closed cases

The boundary rejects:

- tampered request hashes;
- stale generation, plan or policy hashes;
- adapter revision or target mismatch;
- malformed evidence hashes and identifiers;
- `verified` observations without a provider receipt;
- Desired State that is already marked enforced or authorizes infrastructure/external publication.

`mismatch` and `unavailable` remain non-authoritative outcomes and never become verification candidates.

## Release boundary

This work stays within Home Center 0.59, which is inside the allowed three-release horizon from Stable 0.56.0. It does not alter 0.57/0.58 release authority and does not close the remaining real target-node, HA, provider qualification or commercial/legal gates.
