# Home Center 0.59 — Policy Composer v1

Status: WORKING ARCHITECTURE / NOT RELEASE CANDIDATE

## Назначение

Policy Composer переводит роль участника Household и выбранный родителем набор ограничений в точный, объяснимый и проверяемый Desired State. Он является общей частью Home Center и обслуживает оба представления продукта: «Уютный» показывает бытовое объяснение результата, «Полный» — точное техническое представление того же policy state.

Каноническая цепочка остаётся общей:

`Cozy/Full UI → Household/Intent API → Policy Composer → protected Desired State → Execution → Actual State → post-condition verification`

Версия 0.59 закрывает только границу Policy Composer и не переносит в неё функции 0.60 Internet/DNS/Proxy policy.

## Модель v1

`PolicyBundle` содержит ограниченный набор уже существующих RolePreset-параметров:

- `internet_policy`;
- `vpn_allowed`;
- `managed_device_required`;
- `home_files_allowed`;
- `smart_home_control_allowed`;
- `administration_allowed`;
- `external_publication_allowed=false` как неизменяемый инвариант.

`PolicyChangePlan` привязывается к точному Household `snapshot_id`, `resource_version` и `generation`, текущему effective policy, текущему bundle, actor и target member. План детерминирован и содержит понятное русскоязычное описание результата для «Уютного».

`PolicyChangeConfirmation` создаётся только после повторной exact-state revalidation. Подтверждение разрешает только последующую защищённую запись Desired State. Оно само по себе не разрешает provider execution, infrastructure mutation или external publication.

## RolePreset как safety ceiling

RolePreset задаёт верхнюю границу разрешений. Policy Composer может делать политику строже, но не может через пользовательский bundle расширить возможности сверх роли.

Для `child`, например:

- нельзя заменить `filtered` на более разрешающий `full`;
- нельзя включить VPN, administration или smart-home control, если роль это запрещает;
- нельзя снять обязательность managed device;
- допустимо ужесточить Internet policy до `guest` или убрать доступ к домашним файлам.

Для `managed_device_required` используется обратная полярность: `true` строже `false`, поэтому добавление требования допустимо, а снятие уже обязательного требования запрещается.

## Exact-state и evidence integrity

Идентификаторы bundle, plan и confirmation формируются детерминированно из canonical payload. Прямое конструирование объекта с несовпадающим identity должно отклоняться fail-closed.

Перед подтверждением проверяются:

1. тот же Household;
2. тот же `snapshot_id`;
3. тот же `resource_version`;
4. та же `generation`;
5. действующий parent actor;
6. тот же target member и role;
7. повторно построенный target bundle не расширяет RolePreset;
8. повторно построенный plan полностью совпадает с подтверждаемым evidence.

Любой drift требует нового plan.

## Recovery boundary

План фиксирует `recovery_bundle_id`, равный исходному bundle. Это evidence для будущей recovery-операции, а не разрешение выполнить автоматический rollback. Реальное применение и восстановление policy должны идти через отдельные durable Job/Audit/post-condition boundaries.

## Граница безопасности

0.59 Policy Composer не даёт полномочий на:

- выполнение provider-команд;
- изменение сети, DNS, proxy, VPN или firewall;
- автоматическое применение политик к устройствам;
- создание directory/local identities;
- external publication, NAT или port-forwarding;
- обход Identity/RBAC/re-auth;
- автоматический recovery без отдельного admission.

Подробные категории, allow/deny lists, расписания, квоты, session limits и DNS/Proxy enforcement относятся к 0.60 и не входят в эту реализацию.

## Следующие интеграционные шаги внутри 0.59

До готовности 0.59 к promotion необходимо отдельно интегрировать:

- durable protected Desired State store;
- API через Identity/RBAC и server-side actor/member binding;
- explicit re-auth для изменения чувствительных policy-параметров;
- idempotency и durable Audit/Job evidence;
- recovery receipt и read-back результата записи Desired State;
- отображение одного и того же state в «Уютном» и «Полном»;
- backup/restore и upgrade preservation для policy state;
- negative/security qualification точной release identity.

Ни один из этих пунктов не должен обходить существующую цепочку Home Center safety gates.
