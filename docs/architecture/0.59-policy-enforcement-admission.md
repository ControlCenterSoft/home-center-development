# Home Center 0.59 — enforcement admission boundary

Status: runner qualification slice. This boundary is evidence-only and is not a Release Candidate, Stable, provider-execution or commercial-launch claim.

## Назначение

Текущая 0.59-линия уже имеет qualification-bound plan/confirm/execute runtime, exact backend qualification binding и обязательную последующую read-only reconciliation. Перед окончательной release qualification mutation-capable path должен дополнительно иметь отдельное fail-closed admission evidence, не позволяющее перейти от подтверждённого Desired State непосредственно к backend mutation только по факту наличия adapter.

Admission принимает уже существующий exact `home-center.household-policy-enforcement-plan.v1` и связывает решение с точными `backend_id`, `backend_version` и SHA-256 capability/qualification evidence. Он не создаёт второй конкурирующий enforcement-plan contract и не переписывает уже квалифицированную runtime identity.

## Обязательное evidence

`ready=true` возможно только если одновременно подтверждены:

- explicit confirmation;
- актуальная server-side actor authority;
- fresh scoped re-authentication;
- exact Desired State всё ещё current и совпадает с планом;
- backend зарегистрирован намеренно;
- backend имеет typed mutation capability;
- backend независимо имеет read-back capability, необходимую для post-condition verification;
- backend qualification/capability evidence относится к текущей exact backend identity.

Отсутствующее, stale или mismatched evidence возвращается как явный blocker и никогда не трактуется как безопасное значение по умолчанию.

## Граница полномочий

Даже положительный admission decision всегда сохраняет:

- `post_condition_verification_required=true`;
- `fresh_revalidation_required=true`;
- `automatic_retry_authorized=false`;
- `execution_authorized=false`;
- `enforcement_success_claim_authorized=false`;
- `infrastructure_mutation_authorized=false`;
- `external_publication_authorized=false`.

Поэтому этот слой не может сам вызвать backend, опубликовать сервис наружу, изменить инфраструктуру или объявить enforcement успешным. Перед фактическим backend call runtime обязан заново проверить exact state/evidence. Backend acceptance остаётся только промежуточным состоянием; `enforcement_verified=true` допустим исключительно после отдельной свежей reconciliation/post-condition verification.

## Release/security значение

Слой закрывает самостоятельный ИБ prerequisite текущего 0.59 release train: mutation path должен иметь явное подтверждение, scoped step-up, current authority/state и независимую read-back capability до допуска к backend mutation. Concrete production backend и commercial launch clearance остаются отдельными qualification/activation tracks и не получают фиктивный PASS.
