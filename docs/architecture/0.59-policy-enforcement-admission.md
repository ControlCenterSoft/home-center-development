# Home Center 0.59 — policy enforcement admission boundary

Status: source-only runner-free preparation. This boundary is intentionally not a Release Candidate or Stable claim and does not execute a policy backend.

## Purpose

The current 0.59 Policy Composer line can commit protected Household policy Desired State and can reconcile/read Actual State without backend mutation. The next mutation-capable layer must not jump directly from `Desired State committed` to provider execution. This slice adds the intermediate fail-closed admission contract.

An enforcement plan is content-addressed and bound to the exact protected Desired State, including Household/member identity, Desired State generation, source plan, policy identity and policy SHA-256. It is also bound to one backend id/version and one SHA-256 identity for backend capability evidence.

## Required admission evidence

A plan can become `ready=true` only when all of the following are current at the admission boundary:

- explicit user confirmation;
- current server-side actor authority;
- current scoped re-authentication;
- exact Desired State is still current and unchanged;
- backend is deliberately registered;
- backend declares typed mutation capability;
- the same backend declares independent read-back capability required for post-condition verification;
- backend capability evidence still matches the planned identity.

Missing evidence is returned as explicit blocker codes. Unknown or stale evidence is never treated as a safe default.

## Authority boundary

Even `ready=true` is evidence only. Both plan and admission decision keep:

- `execution_authorized=false`;
- `automatic_retry_authorized=false`;
- `infrastructure_mutation_authorized=false`;
- `external_publication_authorized=false`.

`post_condition_verification_required=true` and `fresh_revalidation_required=true` are immutable contract properties. The later mutation runtime must re-read the exact current Desired State, actor authority, scoped re-auth state and backend capability evidence immediately before any backend call.

Provider/backend acceptance must not become Policy `enforcement_verified=true`. A later read-back/reconciliation step must prove the exact post-condition first. Ambiguous mutation outcomes must remain fail-closed and must not be automatically retried.
