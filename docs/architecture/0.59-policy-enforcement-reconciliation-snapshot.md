# Home Center 0.59 — policy enforcement reconciliation snapshot

Status: source preparation only; not runner-qualified; no production backend is registered.

## Purpose

The 0.59 policy-enforcement execution boundary deliberately performs at most one
qualified backend mutation attempt. Backend acceptance is not enforcement success,
and an ambiguous outcome must never be retried automatically.

A crash can occur after Home Center has decided to invoke the backend but before it
can durably classify the result. Reconstructing the old command later from current
Desired State is unsafe because Desired State may already have advanced to another
generation. This layer preserves the exact command identity needed for read-only
reconciliation without widening execution authority.

## Durable sequence

`ReconciliationSnapshotPolicyAdapter` wraps a deliberately registered, qualified
policy mutation adapter.

Before the delegate can be called, Home Center persists and reads back an immutable
snapshot containing:

- exact enforcement plan, Household/member and Desired State generation;
- exact Desired State plan/policy identity and policy SHA-256;
- exact sanitized backend request and its SHA-256;
- exact adapter id/version, adapter artifact SHA-256 and qualification-evidence
  SHA-256;
- `enforcement_verified=false`, `reconciliation_required=true`;
- `automatic_retry_authorized=false` and
  `backend_reinvocation_authorized=false`;
- no secret values and no infrastructure/external-publication authority.

Only after the `invoking` snapshot has been persisted and read back does the wrapper
delegate the one mutation attempt.

A normal return updates the same exact snapshot to `completed/accepted` or
`completed/rejected`. An exception updates it to `in-doubt/ambiguous`. None of these
states verifies enforcement; read-only reconciliation remains mandatory.

## Crash, restart and Desired State drift

An `invoking` snapshot is intentionally uncertain: the process may have crashed
before, during, or after the provider accepted the command. It therefore cannot
authorize another mutation attempt. A newly constructed wrapper after restart sees
the durable snapshot and must also refuse reinvocation.

The snapshot is not derived again from current Desired State. If policy Desired
State advances to a newer generation, the older snapshot remains content-addressed
evidence for the earlier command and can be reconciled independently against the
backend. StateStore backup/restore must preserve the snapshot unchanged.

`build_reconciliation_request_from_enforcement_snapshot()` derives the existing
standard read-only policy reconciliation request from the durable snapshot rather
than current Desired State. This preserves the original Household/member,
generation, Desired State plan, policy identity and policy SHA-256 after drift while
keeping `backend_mutation_authorized=false`, infrastructure mutation disabled and
external publication disabled. A historical reconciliation result still cannot flip
current policy verification flags unless the later verification-transition layer
revalidates that exact binding against current Desired State.

Any malformed or tampered persisted snapshot fails closed when loaded. A request or
adapter-qualification identity mismatch also fails closed before the delegate is
called.

## Authority boundary

This source layer does not:

- register a concrete production backend;
- qualify any backend/provider;
- perform the backend read-back by itself;
- set `enforcement_verified=true`;
- authorize automatic retry or backend reinvocation;
- mutate network/filesystem/infrastructure state;
- authorize external publication;
- claim Release Candidate, Stable, commercial or legal clearance.

The existing 0.59 read-only reconciliation path remains the only intended next step
after accepted, rejected, ambiguous, or crash-uncertain mutation outcomes.

## Qualification handoff

The runner-dependent integration pass should rebase this source onto the actual
qualified 0.59 stack, resolve any overlap with parallel NR1 work, and qualify the
exact integrated head once. Required qualification should include:

1. persistence-before-delegate proof;
2. accepted/rejected/ambiguous outcomes;
3. process-restart recovery from `invoking` and `in-doubt` snapshots without
   backend reinvocation;
4. historical read-only reconciliation request derivation after Desired State drift;
5. snapshot/request/adapter-identity tamper rejection;
6. StateStore backup/restore preservation;
7. JSON contract validation and full repository security/privacy/infrastructure
   checks.

No PR should claim production enforcement until a concrete production-capable policy
backend is separately qualified and the normal commercial/legal release gates are
satisfied.
