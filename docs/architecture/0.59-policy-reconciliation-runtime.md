# Home Center 0.59 — durable read-only policy reconciliation runtime

Status: **Draft stacked runner-qualified follow-up; read-only Actual State verification only; no production authority**.

Base: PR #171 Policy Actual State reconciliation contracts/domain. Public Stable remains 0.56.0 and PR #158 / 0.57 remains the nearest Release Candidate path.

## Scope of this slice

This slice composes the already-qualified reconciliation request/observation/evidence model with Home Center durable runtime state.

It adds:

- a separate `HouseholdPolicyReconciliationRuntimeService`; Policy Composer Desired State commit remains independent from backend observation;
- explicit adapter registration that accepts only adapters declaring `reconciliation_read_only=true`;
- exact parent/administrator Household authorization before reconciliation;
- a durable Job with read-back, exact Desired State re-read, verification and evidence-persistence steps;
- one read-only backend observation per exact deterministic reconciliation request;
- an exact Desired State re-read after backend observation and before evidence acceptance;
- durable reconciliation evidence persisted and read back before the Job becomes `succeeded`;
- idempotent completed replay without a second adapter invocation;
- fail-closed handling of adapter errors, malformed observations and Desired State drift;
- Audit evidence stating that no backend mutation, Desired State verification transition, infrastructure mutation or external publication occurred.

## Deliberate safety boundary

A `verified` reconciliation result proves only that a fresh read-only observation reported the exact policy digest currently requested by the protected Desired State.

This slice **does not**:

- execute or mutate a policy backend;
- set `enforcement_verified=true` in the protected Desired State;
- set `reconciliation_required=false` in the protected Desired State;
- grant policy/backend/infrastructure/network/filesystem/external-publication authority;
- expose a new public HTTP route;
- accept credentials, endpoints, arbitrary commands or generic provider transport;
- claim a concrete backend adapter is production-qualified.

The verified evidence and the existing Desired State are deliberately kept separate. A later transition layer must bind an immutable reconciliation evidence identity/digest into the verified Desired State form and perform an exact StateStore read-back. Callers must not be able to flip verification booleans directly.

## Failure and recovery semantics

- `enforced` with the exact policy digest produces durable `verified` evidence.
- `not-enforced` produces durable `pending` evidence and preserves Desired State.
- digest mismatch produces durable `mismatch` evidence and preserves Desired State.
- `unknown` / `ambiguous` produces durable `blocked` evidence and preserves Desired State.
- stale/future/binding-substituted evidence, malformed observations, adapter failure or Desired State drift fail closed.
- no failed or ambiguous path automatically invokes a backend again.
- a completed exact request is replayed from durable completion evidence without a second backend read.
