# Home Center 0.59 — защищённый переход состояния проверки политики

## Назначение

После сохранения Desired State Home Center считает политику ожидающей применения. Сам факт сохранения Desired State или принятия команды внешней системой не означает успешного применения политики.

Переход в состояние «проверено» разрешён только по уже сохранённому результату read-only сверки Actual State, который доказывает применение ровно той же политики, того же поколения Desired State и того же исходного плана.

## Допустимый переход

Единственный допустимый переход для существующего Desired State:

- `enforcement_verified: false` → `true`;
- `reconciliation_required: true` → `false`.

Все остальные поля Desired State остаются байт-семантически теми же: household/member, generation, plan, policy и SHA-256 политики не меняются. Переход не создаёт новое поколение политики, поскольку не меняет пользовательское намерение.

Любое последующее изменение политики создаёт новое поколение Desired State и снова устанавливает `enforcement_verified=false`, `reconciliation_required=true` до новой независимой проверки Actual State.

## Обязательные доказательства

Перед переходом Home Center повторно проверяет:

- актуальные полномочия родителя/администратора Household;
- завершённое durable-состояние reconciliation;
- exact `request_id` и `evidence_id`;
- статус reconciliation `verified` без blocker;
- точное совпадение household, member, Desired State generation, исходного plan id, policy id и policy SHA-256;
- `enforcement_verified=true` и `reconciliation_required=false` в evidence;
- отсутствие backend-, infrastructure- и external-publication mutation в evidence;
- неизменность текущего защищённого Desired State непосредственно перед записью.

## Конкурентная запись и восстановление

Обновление выполняется как exact compare-and-set внутри одной SQLite-транзакции. Если Desired State изменился между проверкой и записью, переход завершается fail-closed и не перезаписывает более новое состояние.

Операция имеет durable Job и идемпотентную привязку к evidence. Если процесс был прерван после локальной записи, повтор операции может завершить Job только после точного read-back уже проверенного Desired State. Повторный вызов backend для этого не требуется и не разрешается.

## Границы безопасности

Этот переход:

- не вызывает policy backend;
- не повторяет read-back;
- не выполняет backend mutation;
- не изменяет сеть, узлы, firewall, DNS или другие инфраструктурные ресурсы;
- не разрешает внешнюю публикацию;
- не повышает права Household;
- не трактует pending/mismatch/unknown/ambiguous evidence как успех.

Таким образом, флаг `enforcement_verified` отражает только подтверждённый Actual State для конкретного неизменного Desired State, а не сам факт планирования, подтверждения или отправки команды.
