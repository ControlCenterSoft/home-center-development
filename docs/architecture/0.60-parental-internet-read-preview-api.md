# Home Center 0.60 — parental Internet read/preview API

## Purpose

This boundary makes the already integrated 0.60 parental Internet policy visible to the authenticated product UI without turning a UI request into DNS/proxy enforcement authority.

Two operations are exposed:

- `GET /api/v1/household/parental-internet/desired?member_id=<id>&view=cozy|full` reads the current protected parental Desired State for an authorized parent;
- `POST /api/v1/household/parental-internet/decision-preview` produces a side-effect-free ALLOW/DENY preview for the current saved policy.

The endpoint is intentionally read/preview only. It does not expose parental policy plan/confirm, DNS/proxy adapter apply, rollback, external publication or infrastructure mutation.

## Authority and request fences

Both routes reuse the existing Home Center request classification, external-access filtering and authenticated actor boundary inherited from the current V8 handler. The preview POST additionally requires the existing same-origin POST fence and a bounded JSON body.

Household authority is resolved server-side. `ParentalInternetPolicyRuntimeService.desired_state()` requires the authenticated actor to be a currently bound enabled parent with Household administration authority and only permits a child as the policy subject.

A client cannot submit any of the following to the preview operation:

- parental `policy_id`;
- rule-source id/version/SHA-256;
- verified 0.59 policy-base identity;
- provider/backend identity;
- execution/authorization flags.

Unknown request fields are rejected. The server reads those identities from current protected state instead.

## Exact-state binding

Before a preview, the service revalidates the current verified 0.59 child policy base and requires all parental Desired State bindings to remain exact:

- `verified_base_state_sha256`;
- base composed-policy identity;
- base policy SHA-256;
- current protected parental policy structure.

The parental policy is reconstructed through the strict storage/transport validator against the current verified base. A stale base, malformed policy, orphaned state or mismatched binding fails closed and no decision preview is returned.

## Preview semantics

Preview request facts are bounded to domain/category, weekday/time and current usage counters. They are input to the deterministic policy evaluator only after the current server-side policy identity has been established.

The response is explicitly marked:

- `preview_only=true`;
- `enforcement_verified=false`;
- `provider_execution_authorized=false`;
- `infrastructure_mutation_authorized=false`;
- `external_publication_authorized=false`.

A preview therefore explains what the saved policy would decide for the supplied facts. It is not Actual State and must never be used as proof that DNS/proxy enforcement occurred.

## Cozy and Full projections

`view=cozy` returns the existing Russian household-facing explanation (`Доступ разрешён правилами` / `Доступ запрещён правилами`) and bounded reason text.

`view=full` returns the existing technical decision projection for operators. Neither projection grants mutation authority.

The saved-policy GET uses the same split: Cozy reports the household-facing state `Семейные правила сохранены / Ожидают применения и проверки`; Full provides the bounded technical Desired State projection.

## Packaging and release boundary

`api_v9.py` and `parental_internet_policy_read_api.py` are required members of the reproducible Home Center wheel. This prevents an artifact from passing release qualification while silently omitting the production handler selected by `server.py`.

This slice does not change the canonical Stable version and does not claim 0.60 Release Candidate/Public Stable readiness. It closes a source/runtime visibility gap only. Parental Desired State mutation with scoped re-auth, concrete DNS/proxy execution, read-back/verification persistence, recovery qualification and release/commercial gates remain independent 0.60 work.
