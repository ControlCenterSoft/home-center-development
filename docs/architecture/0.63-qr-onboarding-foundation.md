# Home Center 0.63 — QR guest/device onboarding foundation

Status: development architecture; not Release Candidate and not Public Stable.

## Purpose

0.63 introduces a bounded QR onboarding foundation for temporary guest access and safe device onboarding. A QR code is a short-lived bootstrap mechanism only; it is not an administrative credential and must never contain a long-lived password, API token, domain credential or emergency-admin secret.

## Invitation model

Only a current Household parent may issue an invitation. The immutable invitation is bound to:

- exact Household and issuer member identity;
- subject type: `guest` or `device`;
- a bounded guest scope or one exact device identity;
- SHA-256 of the one-time onboarding code;
- creation and expiration timestamps;
- single-use semantics and explicit revocation support.

The durable invitation stores only the code digest. The raw onboarding code exists only in the ephemeral QR payload. TTL is bounded to 60–1800 seconds and `max_uses=1`.

## Guest boundary

A guest invitation may grant only the explicitly enumerated temporary guest scopes. It cannot create an administrator, inherit parent permissions, grant Home Center administration, enable external publication or bypass existing Household policy. Expiration, revocation or prior consumption fail closed.

## Device boundary

A device invitation is bound to one exact device identity and carries no guest scope. Successful code presentation only produces a redemption plan. Device binding remains a later explicit-confirmation mutation and must revalidate the current Household/device state before changing anything.

## Redemption semantics

Code presentation performs only side-effect-free validation:

1. invitation is current and not expired;
2. invitation is not revoked;
3. invitation has not already been consumed;
4. presented code hashes to the exact invitation digest;
5. invitation identity and subject binding are consistent.

A successful check produces a deterministic redemption plan with `explicit_confirmation_required=true`. Account creation, device binding, provider execution, infrastructure mutation and external publication remain unauthorized.

## Revocation and recovery

Revocation is first-class evidence. Once revoked, the invitation cannot be redeemed even if the QR payload is still within TTL. Consumption is also fail-closed and single-use. A future persisted execution layer must make consume/revoke transitions atomic and idempotent, preserve Audit evidence, and never resurrect an expired/revoked/consumed invitation after restart or restore.

## Cozy / Full UI

`Уютный` may show simple actions such as “Пригласить гостя” or “Подключить устройство”, the remaining invitation lifetime and an immediate “Отозвать” action. It must clearly say that the QR is temporary and one-time.

`Полный` may additionally show invitation identity, subject, scope/device binding, creation/expiry, consumed/revoked evidence and Audit references. Neither UI may display the durable token digest as a reusable credential or log the raw onboarding code.

## Security boundary

- parent-only issuance;
- short TTL and one-time use;
- raw code never persisted in the invitation;
- no long-lived or administrative credential in QR;
- no implicit account creation or device binding;
- no privilege escalation from guest/device onboarding;
- revocation and expiration are fail-closed;
- no external publication or generic execution authority.
