# Home Center 0.59 — exact policy backend qualification binding

Status: **non-runner preparation; no production wiring; no release/publication authority**.

Public Stable remains 0.56.0. Allowed development horizon remains 0.57/0.58/0.59. This slice continues the existing 0.59 enforcement/backend-qualification line and does not duplicate the already prepared enforcement HTTP boundary, mutation runtime, reconciliation snapshot or real-backend qualification evaluator.

## Problem closed by this preparation

The enforcement runtime must never trust a concrete adapter merely because it self-declares `policy_backend_qualified=true` or presents syntactically valid digest strings. Qualification is meaningful only when the exact adapter identity is derived from one exact `home-center.policy-backend-qualification.v1` decision that is itself bound to:

- Home Center version and immutable revision;
- exact candidate artifact SHA-256;
- backend/adapter identity and semantic version;
- adapter artifact SHA-256;
- content-addressed real-backend qualification evidence.

A persisted enforcement plan must remain bound to that same qualification after restart. Re-registering a different adapter build, a different candidate qualification or different qualification evidence must fail closed before durable Job admission and before any backend mutation invocation.

## Added boundary

`household_policy_enforcement_qualification_binding.py` introduces a non-authorizing registration/binding projection:

- `QualificationBoundPolicyAdapterRegistration` can only be built through the existing `QualificationBoundPolicyMutationAdapter` exact-evidence constructor;
- `HouseholdPolicyEnforcementQualificationBinding` contains only review-safe identity/evidence digests and explicit false authority flags;
- the binding is closed and serializable through `household-policy-enforcement-qualification-binding.v1.schema.json`;
- restart-safe revalidation compares the persisted binding with the current qualification-bound registration;
- adapter/candidate/evidence drift fails with `household_policy_enforcement_qualification_binding_stale`;
- self-declared flags on an arbitrary adapter are not accepted as a qualification registration;
- revalidation is side-effect free and never invokes the backend.

This preparation does **not** change the existing production composition root or enforcement runtime behavior yet. That integration must be a separate runner-qualified slice.

## Required runner-qualified integration

The next integration slice should preserve these invariants:

1. The composition root registers policy mutation adapters only as `QualificationBoundPolicyAdapterRegistration` objects produced from exact qualified evidence.
2. Enforcement `plan` persists the complete `binding.to_dict()` and includes it in the deterministic plan identity.
3. The user-visible/technical confirmation copies the exact binding rather than only a backend name.
4. Immediately before durable Job admission, revalidate current Household/Desired State **and** the exact persisted qualification binding.
5. Immediately before the single backend call, repeat the exact qualification-binding revalidation. Any drift fails closed and performs zero backend calls.
6. Job preflight/evidence and Audit retain the candidate/adapter/evidence digests required to prove which qualified backend build was invoked.
7. A backend acceptance result still means only `reconciliation_required=true`; it never sets verified enforcement state.
8. Automatic backend retry remains disabled. Ambiguous outcomes remain reconciliation/recovery cases, not implicit mutation retries.
9. No credential values, provider endpoints, arbitrary commands, infrastructure mutation authority or external-publication authority enter the binding.
10. Qualification binding is not release authority and does not substitute for 0.57 target-node/HA/provider Stable evidence.

## Test intent

The prepared regression tests cover exact binding creation, closed-schema validation, restart with the same binding, candidate/evidence drift, tampering, forbidden authority flags, unknown fields, bounded review projection and rejection of self-declared qualification flags without the exact evidence-derived registration object.

No GitHub Actions workflow, workflow dispatch, rerun or PR is created by this non-runner slice.
