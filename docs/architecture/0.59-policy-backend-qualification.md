# Home Center 0.59 — exact-bound policy backend qualification

Status: **NR2 source preparation; no PR; no hosted qualification; no production backend registered**.

Public Stable remains 0.56.0. This work is limited to the permitted Stable+3 horizon and belongs to 0.59. The nearest Release Candidate path remains 0.57; nothing in this source slice changes RC, Stable, commercial/legal or external-publication status.

## Purpose

The 0.59 Policy Composer line already separates protected Desired State, explicit policy-enforcement confirmation, a single backend mutation attempt, read-only reconciliation and verified effective-state projection. A production backend must not become trusted only because its Python object declares `policy_backend_qualified=true`.

This slice adds a content-addressed qualification decision for a concrete policy backend and a narrow handoff into the existing enforcement adapter boundary. Qualification is evidence evaluation only: it invokes no backend and grants no mutation authority.

## Exact identity binding

Qualification evidence is bound to:

- Home Center semantic version and exact source revision;
- exact candidate artifact SHA-256;
- backend/adapter identity and adapter semantic version;
- exact adapter artifact SHA-256;
- content-addressed execution transcript and environment evidence.

Malformed identities, cross-backend adapter identity and invalid digests fail closed. The resulting evidence digest covers the complete semantic evidence object, including the safety observations, so changing a safety result changes the evidence identity.

## Required real evidence

A backend is `qualified=true` only when evidence proves all of the following for the exact candidate and adapter:

- real backend and real target were exercised;
- plan and confirmation contracts were validated;
- execution remained bound to the exact protected Desired State;
- secret values are absent from evidence;
- a confirmed operation invokes the backend at most once;
- ambiguous outcome fails closed and automatic retry remains disabled;
- backend acceptance still requires reconciliation and post-condition read-back;
- the verified-state transition remains a separate boundary;
- restart recovery and the recovery path were exercised;
- infrastructure scope stayed bounded;
- external publication remained forbidden.

Missing evidence produces explicit blockers rather than a partial-success claim.

## Registration handoff

`registration_metadata_from_policy_backend_qualification()` accepts only a qualified decision with no blockers and requires exact equality with the expected version, revision, candidate artifact, backend identity, adapter version and adapter artifact. It returns only the adapter identity/version/artifact digest and qualification-evidence digest required by the enforcement runtime.

`QualificationBoundPolicyMutationAdapter` additionally binds those qualified values to a concrete mutation-capable adapter before exposing the existing `policy_backend_qualified` registration surface. Adapter identity or artifact drift fails closed. The wrapper delegates only the typed `apply_policy()` call; it does not create new mutation scope.

The intended production integration is therefore:

1. execute a bounded qualification procedure against the exact candidate, real backend and real target;
2. evaluate its content-addressed evidence;
3. bind the qualified decision to the exact concrete adapter;
4. register only the qualification-bound wrapper with the enforcement runtime;
5. retain the existing explicit plan/confirm/execute boundary;
6. require independent read-only reconciliation and verified-state transition before reporting enforcement success.

## Authority boundaries

A qualification decision always has:

- `backend_mutation_authorized=false`;
- `release_authorized=false`;
- `external_publication_authorized=false`.

The decision therefore proves that a backend/adapter passed the required evidence checks; it does not itself authorize a policy mutation, a release, network/filesystem/infrastructure changes or external publication. Mutation authority remains the responsibility of the separately confirmed enforcement execution boundary.
