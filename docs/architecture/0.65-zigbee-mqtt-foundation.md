# Home Center 0.65 — ZigBee/MQTT foundation

Status: source-only plan/read-model foundation. This document does not claim Release Candidate or Public Stable readiness.

## Product boundary

0.65 introduces provider-neutral evidence and planning contracts for a ZigBee coordinator or MQTT bridge. The foundation is intentionally non-executing: it can describe a coordinator, discovered devices, rooms/capabilities, battery/link-quality evidence and exact pair/unpair/backup plans, but it cannot open a pairing window, remove a device, write coordinator configuration, invoke a provider, change infrastructure or publish anything externally.

Observed state is freshness-bound. Future, stale, unavailable, duplicate or coordinator-mismatched evidence cannot be treated as current. Pair/unpair planning is allowed only from a current content-addressed inventory snapshot. A pre-operation network backup is mandatory in the plan; backup and restore execution remain separately unauthorized until a later typed Change/Job implementation provides verification and recovery semantics.

## HA truthfulness

The 0.65 foundation never claims HA. USB/serial coordinators are explicitly represented as a single physical coordinator. TCP/MQTT-backed observations also keep `ha_supported=false` until a future provider profile has its own failure/recovery qualification. Automatic failover is always unauthorized in this source slice.

## Cozy / Full UI

The Cozy projection exposes only household language: current/stale/unavailable state, device count when trustworthy, attention state and a plain HA limitation. It does not expose provider endpoint/fingerprint or technical coordinator details. The Full projection may expose bounded technical evidence and the exact inventory digest. Neither projection authorizes mutation.

## Security and commercial boundary

No raw pairing/install code, password, token, broker credential or long-lived administrative credential is modeled by these contracts. Endpoint identity, when available, is represented only as a SHA-256 fingerprint. The slice adds no third-party runtime dependency and creates no new redistribution obligation. External publication, remote access and provider execution remain hard-false.

## Required follow-up before any 0.65 execution claim

A later slice must add a deliberately registered provider adapter, exact authorization and confirmation, durable Change/Job admission, a pre-change coordinator backup, typed execution, authoritative read-back, post-condition verification, Audit evidence and recoverable failure behavior. Pairing/provider acceptance alone must never be treated as successful device onboarding. Release identity, install/upgrade/rollback, security/reproducibility qualification and Public Stable promotion remain separate release gates.
