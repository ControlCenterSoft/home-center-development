# Home Center 0.64 — Recommendations UI truthfulness boundary

Status: source-only read projection. No execution authority is introduced.

## One evidence source, two interfaces

«Уютный» and «Полный» consume the same exact `safe-auto-repair-recommendation` evidence. «Уютный» translates the decision into short household language; «Полный» may display the exact recommendation/resource generation, evidence digest, policy identity/digest, risk and blockers. Neither interface has a separate execution path.

## Truthfulness rules

Eligibility is not repair success. An eligible card must say that the safety admission checks passed, but the repair has not yet run and no result has been verified. Until the separate execution/post-condition path is qualified, the UI keeps `execution_available=false`, `repair_completed=false` and every execution/provider/infrastructure/publication authority false.

A blocked recommendation is shown as blocked evidence with an explicit human-readable reason. It is never silently hidden, upgraded to eligible, or displayed as a completed repair.

Stored history uses the same projection. Any history row that attempts to carry execution/provider/infrastructure/publication authority is rejected fail-closed. An eligible record with blockers, or a blocked record without a blocker, is inconsistent and rejected.

## Cozy wording

The normal eligible headline is «Можно безопасно подготовить исправление». This is intentionally weaker than «Исправлено»: it communicates that the recommendation passed admission requirements while preserving the distinction between recommendation, Job execution and authoritative post-condition verification.

Blocked cards use «Автоматическое исправление недоступно» plus bounded Russian explanations for policy, risk, recovery, verification, provider, infrastructure or external-publication blockers.

## Remaining 0.64 work

This read projection does not replace canonical StateStore migration, authenticated API wiring, durable Job execution, action-specific adapter qualification, post-condition verification, Audit/recovery history, restart/reconciliation, install/upgrade/security/packaging qualification or Public Stable promotion.
