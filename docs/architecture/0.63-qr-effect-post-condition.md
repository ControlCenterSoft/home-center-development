## Why this boundary is required

A consumed or revoked QR invitation proves only the one-time invitation transition. A durable typed effect Job proves only that work was admitted. Neither fact proves that guest access, device binding or revocation is effective in authoritative product state.

The verification path therefore remains separate:

`terminal QR receipt → exact handoff → durable typed Job → verification request → authoritative read-only observation → positive verification receipt`.

Only the final receipt may set `post_condition_verified=true` and `effect_success_claimed=true`.

## Read-only observation

`QrOnboardingEffectObservation` is content-addressed and bound to:

- exact verification request digest;
- exact handoff digest;
- exact effect Job ID and effect kind;
- Household/member/subject/device identity;
- the bounded guest scope from the handoff (`internet.guest` only for guest onboarding);
- expected and observed post-condition;
- authoritative reader identity;
- bounded observation freshness window, maximum 300 seconds.

The observation is never success evidence by itself. It always carries:

- `read_only=true`;
- `post_condition_verified=false`;
- `effect_success_claimed=false`;
- effect/provider/infrastructure/publication authority = false.

`unknown`, `not-satisfied`, stale, future-dated, cross-Job, cross-handoff, scope-relabelled or digest-tampered observations fail closed.

## Positive verification receipt

`verify_qr_onboarding_effect_post_condition()` emits a content-addressed `QrOnboardingEffectVerificationReceipt` only when:

1. the verification request still matches its exact immutable handoff;
2. the observation matches the exact request/handoff/Job/target/scope binding;
3. the observation evidence digest is intact;
4. the observation is current and within its bounded freshness window;
5. observation state is `satisfied`;
6. observed post-condition exactly equals the requested post-condition.

Only then the receipt states:

- `authoritative_readback_verified=true`;
- `post_condition_verified=true`;
- `effect_success_claimed=true`.

The receipt does **not** authorize another mutation. Effect execution, durable state change, provider execution, infrastructure mutation and external publication remain false.
