# Home Center — интерфейс «Уютный» и Household/Intent Layer

Status: ACCEPTED / FUNDAMENTAL ARCHITECTURE DECISION

## Назначение

«Уютный» — обязательный второй интерфейс Home Center. Это не отдельный продукт, не тема оформления и не урезанная редакция. Его задача — дать домашнему пользователю максимальный результат при минимальном количестве действий и не заставлять работать с инфраструктурными сущностями без необходимости.

Главное UX-правило: Home Center знает, как устроена инфраструктура; пользователь формулирует бытовую цель.

## Два уровня интерфейса

- **«Уютный»** — mobile-first режим для повседневного домашнего управления, крупные элементы, готовые безопасные сценарии и отсутствие прямых опасных операций.
- **«Полный»** — профессиональный режим со всеми техническими параметрами, узлами, ролями, сетью, хранилищами, сервисами, политиками, журналами и диагностикой.

Оба режима являются представлениями одного Home Center и работают поверх общих API, Desired/Actual State, authorization, audit и recovery semantics. «Уютный» не получает отдельного execution path.

## Переключение режимов

Начиная с 0.46.0 интерфейс обязан предоставлять постоянное переключение **«Уютный» ↔ «Полный»**.

Правила:

- для обычного домашнего использования режимом по умолчанию является «Уютный»;
- пользователь может перейти в «Полный» одним явным действием;
- выбранный режим сохраняется для последующих открытий интерфейса;
- переход между режимами не изменяет Desired State, права, политики или инфраструктуру;
- критическая диагностика и опасные операции не переносятся в «Уютный» как обычные бытовые действия.

## Основное меню «Уютный»

Первая полноценная навигационная модель включает три верхнеуровневых раздела:

1. **Домой** — сводное состояние дома, важные предупреждения, интернет/VPN, домашние сервисы, резервные копии и безопасные рекомендации.
2. **Семья** — люди как основные сущности, роли `parent`, `child`, `guest`, связанные устройства и итоговые политики.
3. **Мой дом** — Интернет, Умный дом, Фильмы и музыка, Игры, Файлы, Сервер, Резервные копии и дополнительные домашние сервисы.

В бытовом режиме не должны без необходимости показываться конкретные backend-технологии вроде Samba, PostgreSQL, Zigbee2MQTT, TorrServer, WireGuard или container runtime. Они остаются provider-реализациями и доступны в полном интерфейсе при наличии соответствующих возможностей.

## Household/Intent architecture

Каноническая цепочка:

`Cozy UI → Household/Intent API → Policy Composer → Core API / Desired State → Reconciler / Execution → Actual State → Post-condition verification`

Базовые доменные сущности: `Household`, `FamilyMember`, `HouseholdRole`, `ManagedDevice`, `RolePreset`, `PolicyBundle`, `EffectivePolicy`, `UserIntent`, `RecommendedAction`.

## Safety invariants

Для «Уютного» обязательны:

- safe-by-default;
- default deny для неподтверждённых privileged-возможностей;
- plan/desired-state до инфраструктурной мутации;
- stale-state protection;
- idempotency;
- authorization и audit;
- post-condition verification;
- recovery/rollback для поддерживаемых изменений;
- отсутствие автоматического external publication, NAT/port-forwarding и иных рискованных функций без явного разрешения.

## Mobile-first UX

- крупные touch targets;
- одна основная задача на экран;
- минимум полей ввода;
- бытовые формулировки вместо provider terminology;
- готовые пресеты вместо ручной сборки политик;
- прогрессивное раскрытие деталей;
- QR/onboarding flows там, где это уменьшает количество ручных действий.

## Актуальная release boundary

Историческая привязка «Уютного» к 0.24/0.25 была вытеснена фактической последовательностью backend-релизов и больше не является действующей release boundary.

Актуальная граница:

- **0.26–0.28** — фундамент Household/Intent, versioned household state и exact-state intent planning;
- **0.29–0.45** — параллельное развитие module/runtime, execution и других core boundaries; номера этих релизов уже заняты фактической разработкой;
- **0.46.0** — пользовательская оболочка режимов и постоянное переключение «Уютный»/«Полный», сохранение выбора, «Уютный» по умолчанию;
- **0.47.0** — первый полноценный mobile-first интерфейс «Уютный» с меню «Домой», «Семья», «Мой дом»;
- **0.48+** — последовательное подключение реальных household actions: role-driven provisioning, учётные записи и профили, internet/DNS, лимиты, VPN, managed-device policies, домашние providers, рекомендации, QR-гости и безопасный auto-repair.

Начиная с 0.46 каждая пользовательская capability должна определять техническое представление в Full/Core API, бытовое представление в Household/Intent API, mapping в Desired State, safety gates, permissions, post-condition verification и recovery behavior.
