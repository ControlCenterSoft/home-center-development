# Home Center 0.65.0

Status: source preparation only; not Release Candidate and not Public Stable.

Authoritative Public Stable baseline for this work is Home Center 0.63.0. Home Center 0.64 remains the nearer release train and must complete its own release cycle independently.

## Scope

0.65 introduces the provider-neutral ZigBee/MQTT foundation from the authoritative Roadmap. The current source-only slice models:

- exact coordinator observations for ZigBee or MQTT-bridge profiles;
- discovered device identity, rooms/capabilities, battery and link-quality evidence;
- explicit current/stale/unavailable freshness semantics;
- content-addressed inventory snapshots;
- plan-only pairing and unpairing with bounded pairing windows;
- mandatory pre-operation backup planning;
- content-addressed coordinator-configuration backup evidence;
- fail-closed verification states `verified` / `failed` / `unknown`;
- deterministic recovery binding between an exact operation plan and an exact verified pre-operation backup;
- explicit single-physical-coordinator HA limitation;
- Cozy and Full read-only projections without mutation authority.

## Safety boundary

The 0.65 source foundation does not open pairing mode, remove a device, write coordinator configuration, invoke a provider, restore a backup, mutate infrastructure or publish anything externally.

A `verified` backup is recovery evidence only. It contains hashes and bounded identity/timestamps, not raw ZigBee network configuration, network keys, MQTT credentials, tokens or pairing codes. `failed` and `unknown` backups cannot become restore-eligible. Recovery binding fails closed on coordinator or inventory drift.

Pairing/provider acceptance, backup creation and recovery availability are all distinct from successful device onboarding. A later execution path must still use Identity/RBAC, explicit confirmation, durable Change/Job admission, typed provider execution, authoritative read-back, post-condition verification, Audit evidence and restart-safe recovery before user-visible success.

## HA boundary

USB/serial coordinators remain an explicit single physical dependency. `ha_supported=false` and automatic failover remains unauthorized. TCP/MQTT transport also does not imply HA; a future provider profile must pass its own failure/recovery qualification before any HA claim.

## Commercial and security boundary

The current foundation adds no third-party runtime dependency and no remote-service client dependency. It creates no new redistribution obligation and does not claim provider qualification, external-publication readiness, commercial-launch/legal clearance or production HA support.

## Required follow-up

Before 0.65 can become a release candidate, later slices must add deliberate provider adapter registration, authorization/confirmation, durable execution/reconciliation, verified restore execution, Audit/history, restart/recovery behavior, compatibility with the Home Center backup model, install/upgrade/rollback qualification, security/privacy/reproducibility checks and final release packaging/promotion.
