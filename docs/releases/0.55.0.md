# Home Center 0.55.0

Статус: development-кандидат; подготовлен без продвижения в release/main и без запуска CI.

## Назначение

Home Center 0.55.0 вводит канонический read-only индекс совместимости Home Service / Market-модулей поверх уже валидированных compatibility state. Индекс предназначен для безопасного сводного ответа на вопрос, какие модули совместимы с текущей версией Home Center и какие из них заблокированы либо требуют повторной проверки.

Эта версия не устанавливает модули, не запускает их, не изменяет инфраструктуру и не публикует сервисы наружу.

## Канонический индекс

Добавляется схема `home-center.module-home-service-compatibility-index.v1` и детерминированный индекс со следующими свойствами:

- один элемент на `module_id`; дубликаты отклоняются;
- элементы сортируются по `module_id`, поэтому одинаковый набор evidence даёт одинаковую canonical identity;
- `resource_version` вычисляется по canonical JSON и связывает содержимое индекса с его идентичностью;
- `etag` и `index_id` проверяются относительно `resource_version`;
- compatibility state принимается только после строгой валидации;
- state из другой версии Home Center отклоняется;
- stale state не выдаётся за актуальный compatible/blocked результат.

Сводный `overall_status` формируется fail-closed:

- если есть хотя бы один `stale`, результат `stale`;
- иначе при наличии хотя бы одного `blocked` результат `blocked`;
- только при отсутствии stale/blocked результат `compatible`.

## Граница безопасности и коммерческая граница

Индекс является только доказательством совместимости. Он никогда не выдаёт разрешение на установку или выполнение модуля. Все authority-флаги остаются `false`:

- `admission_authorized=false`;
- `installation_authorized=false`;
- `execution_authorized=false`;
- `production_mutation_enabled=false`;
- `external_publication_authorized=false`.

Совместимость не заменяет лицензионный entitlement, пользовательское подтверждение, admission policy, security policy или отдельную процедуру установки/активации Market-модуля.

## Single-node / HA

Индекс не требует отдельного HA-компонента и не создаёт distributed state. Он строится из уже проверенных compatibility state и может одинаково использоваться в single-node и HA-конфигурации. Источником истины остаётся валидированное состояние модулей, а не локальная эвристика UI.

## Требования перед release qualification

Перед переносом в release/main должны быть отдельно подтверждены:

1. отсутствие расхождений с актуальными 0.53/0.54 изменениями после их reconciliation;
2. включение `module_home_service_compatibility_index.py` в обязательный состав квалифицированного wheel;
3. JSON-schema validation контракта;
4. тесты canonical identity, duplicate rejection, version mismatch, stale handling и authority flags;
5. сохранение privacy/infrastructure-neutrality границ;
6. отсутствие автоматической установки, запуска или лицензирования модулей на основании одного compatibility index.
