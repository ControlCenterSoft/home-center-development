# Home Center 0.43.0

Status: release candidate — qualification in progress.

## Scope

Home Center 0.43.0 binds the canonical Home Service contract requirement set
introduced in 0.42.0 to the exact Home Service compatibility evidence that
actually evaluated those requirements.

`home-center.module-home-service-contract-requirement-binding.v1` gives this
relationship a deterministic `mhsrb-*` identity. The evidence binds one exact
`mhscr-*` requirement set to one exact `mhscb-*` compatibility binding and
records the Home Center version, module identity/version, Home Service identity,
service-profile digest, canonical required contract revisions and compatibility
status.

The binder reconstructs compatibility from the canonical requirement set,
module contract/admission binding and Home Service profile. A requirement set
whose Home Center version, module identity/version, service identity or required
contract set does not match the resulting compatibility context is rejected
fail-closed.

Serialized requirement-binding evidence is also validated fail-closed: the
field set is closed, authority flags must remain false, identifiers and digests
must be canonical, contract ordering must be canonical, and the deterministic
`mhsrb-*` identity is recomputed before evidence is accepted.

This makes requirement provenance explicit without changing the existing v1
requirement-set or Home Service compatibility contracts.

## Safety boundary

Requirement-binding evidence is descriptive only. It does not authorize
admission, installation, execution, production mutation or external
publication. Blocked compatibility remains valid evidence but never grants
runtime authority.

The contract is topology-neutral and infrastructure-neutral. It adds no
Jobs/Operations behavior, Cluster/HA orchestration, placement semantics or
release-promotion logic. Existing authentication policy is unchanged.

No persistent-state migration is required.

## Verification boundary

The source package includes the runtime contract, serialized-evidence validator,
closed JSON Schema and targeted unit/contract tests. Official publication
requires the repository's complete qualification, security/privacy and release
governance checks for the exact candidate revision.
