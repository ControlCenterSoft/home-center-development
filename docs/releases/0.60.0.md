# Home Center 0.60.0

Status: official release.

Release profile: `single-node-core`.

## Назначение

Home Center 0.60.0 добавляет безопасный родительский Internet/DNS/Proxy policy layer для child-профилей поверх официального Home Center 0.59.0 Public Stable. Релиз сохраняет единый fail-closed путь Home Center: verified base → plan → explicit confirm → protected Desired State → typed provider boundary → Actual State read-back → verification.

## Что входит в релиз

- детерминированные allow/deny domains и categories;
- точная привязка к `rule_source_id`, версии и SHA-256 источника правил;
- расписания, daily/weekly quotas, continuous-session limits, breaks, grace и bonus;
- default deny и объяснимый результат ALLOW/DENY;
- строгая storage/transport reconstruction против exact verified 0.59 child-policy base;
- parent-only plan и отдельное explicit confirm;
- durable Job/Audit и protected parental Desired State с exact Household/base/evidence/generation binding;
- idempotent replay и fail-closed rejection stale/tampered/competing state;
- backup/restore qualification для parental Desired State;
- typed provider-neutral DNS/proxy adapter capabilities, apply/readback/observation/rollback contracts;
- read-only post-condition verifier с freshness и exact Desired State/policy/provider-operation binding;
- reproducible wheel и node deployment artifact обязаны содержать интегрированный 0.60 parental-policy runtime.

## Safety boundary

Сохранение parental Desired State не означает, что DNS/proxy policy применена. Provider command acceptance также не является enforcement success. До отдельного подтверждённого post-condition transition сохраняются:

- `enforcement_verified=false`;
- `reconciliation_required=true`;
- `dns_policy_applied=false`;
- `proxy_policy_applied=false`;
- infrastructure mutation и external publication не разрешаются автоматически.

В bounded `single-node-core` профиле 0.60.0 не заявляется universal concrete DNS/proxy provider execution. Concrete production adapter должен проходить отдельную exact-bound qualification; при его отсутствии соответствующая фактическая enforcement capability остаётся fail-closed/disabled/unclaimed. Автоматический retry неоднозначного provider outcome запрещён.

Multi-node HA / automatic failover также не заявляются без отдельной qualification. Отсутствие этих optional claims не превращается в выдуманный PASS и не расширяет полномочия релиза.

## Install / upgrade / rollback

Release qualification обязана использовать точные immutable identities: официальный Public Stable `0.59.0` как baseline и exact `0.60.0` candidate без переписывания candidate source во время теста. Поддерживаемый переход 0.59.0 → 0.60.0 должен подтверждать install/upgrade, readiness, restart, сохранность пользовательского состояния и локальных credentials, а также rollback обратно к 0.59.0.

## Security и release evidence

Public Stable promotion допускается только после exact-head Home Center CI, Python 3.12/3.13/3.14, reproducible artifact qualification, CodeQL security-extended/fail-closed gate, Public repository privacy boundary, Infrastructure neutrality и полного immutable release artifact set с checksum/provenance/manifest evidence.

False Success является release blocker: неподтверждённое или неоднозначное состояние не может быть представлено как применённая parental policy.

## Commercial / legal boundary

0.60.0 не добавляет новую стороннюю runtime dependency или bundled concrete DNS/proxy provider. Технический Public Stable не является автоматическим commercial launch clearance. Support/licensing claims и provider-specific redistribution obligations требуют отдельного evidence, если соответствующий concrete provider будет добавлен или коммерчески заявлен.

## Совместимость

Home Center 0.60.0 остаётся полноценным local-first single-node продуктом. Не заявленные HA/provider/commercial возможности остаются выключенными или неподтверждёнными, не блокируя технически квалифицированный bounded Stable профиль.
