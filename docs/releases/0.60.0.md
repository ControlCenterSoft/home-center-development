# Home Center 0.60.0 — Parent Internet/DNS/Proxy Policy

Status: development foundation; **not Release Candidate and not Public Stable**.

Canonical published Public Stable baseline is 0.57.0. This release is the third and furthest release permitted by the current three-release development window (0.58–0.60). No 0.61+ functionality is included.

## Product result in the current source slice

0.60 introduces a child-only parental Internet policy model on top of the exact verified 0.59 Policy Composer state. The current source implements:

- category allow/deny rules;
- domain allow/deny rules with canonical IDNA normalization;
- exact rule-source identity, version and SHA-256 binding;
- bounded weekly schedule windows;
- daily and weekly usage quotas;
- continuous-session limit;
- mandatory break, bounded grace and bounded daily bonus;
- deterministic `ALLOW` / `DENY` decision reasons;
- strict default-deny behavior;
- Russian Cozy explanations and exact Full UI projections;
- closed query, policy, decision, plan/confirm, Desired State and commit-receipt contracts;
- protected parent-only plan → explicit confirm → durable Job → parental Desired State → read-back → Audit workflow;
- exact binding to the current verified 0.59 child policy, its full SHA-256, exact current 0.59 Desired State and verification evidence;
- stale/tampered Household, verified-base and competing parental Desired State rejection;
- backup/restore qualification code for parental Desired State, Job/evidence and Audit preservation;
- typed provider-neutral DNS/proxy enforcement boundary with explicit adapter capabilities, exact Desired State apply request, provider-acceptance result, read-only Actual State read-back, observation and bounded rollback contracts;
- closed Draft 2020-12 schemas for the enforcement apply/read-back/observation/rollback transport boundary;
- fail-closed schema/test coverage that rejects ambiguous observation, mutation/publication authority in read-back evidence, and false `enforcement_verified`/`rollback_verified` claims.

## Fail-closed precedence

An explicit allow never bypasses parental time controls. Decision order is:

1. exact policy/Household/member binding;
2. exact rule-source version/SHA-256 binding;
3. explicit domain deny;
4. allowed schedule;
5. weekly quota;
6. daily quota plus bounded bonus;
7. continuous-session limit plus bounded grace and required break;
8. explicit domain allow;
9. category deny/allow;
10. unknown classification or category not explicitly allowed → `DENY`.

An empty category allow-list therefore does **not** mean allow-all.

## 0.59 dependency

0.60 policy planning is rejected unless the child has a current protected 0.59 verified Desired State projection. The verified projection must still match the current 0.59 Desired State byte-semantically through its SHA-256 binding and must still match the current child RolePreset. Old verification evidence cannot be reused after a newer unverified 0.59 policy write.

## Enforcement adapter boundary

The adapter registry is empty by default. Home Center does not discover or enable an enforcement backend implicitly. A future concrete adapter must explicitly declare DNS, proxy and read-back capabilities; both DNS and proxy plus Actual State read-back are mandatory for this 0.60 policy profile.

The apply request is bound to the exact protected parental Desired State digest, verified 0.59 base-state digest, plan/generation, policy identity/digest and adapter identity/version. It carries no credential values and grants no external-publication authority.

Provider acceptance is only an acknowledgement that an adapter accepted the operation. The apply result is hard-bound to:

- `post_condition_verified=false`;
- `enforcement_verified=false`;
- `actual_state_readback_required=true`.

Actual-State read-back is read-only and grants no backend, infrastructure or external-publication mutation authority. A valid observation must bind the exact operation/Desired State/policy identity. `enforced` DNS/proxy planes require policy digests; unknown or not-enforced planes require an explicit bounded blocker. Even a fully matching observation remains evidence for a later verification boundary and does not itself mutate protected Desired State.

Rollback is separately typed and bound to the failed Desired State/policy plus recovery evidence. Adapter rollback acceptance is not recovery success: rollback results remain `post_condition_verified=false`, `rollback_verified=false` and require a subsequent Actual-State read-back.

## Safety boundary

The protected 0.60 parental policy workflow persists Home Center Desired State. The typed adapter layer defines a future execution/recovery contract but does not register a concrete production adapter and does not configure DNS, proxy, firewall, routing, browser/device settings or VPN by itself.

Every persisted policy/receipt keeps:

- `enforcement_verified=false`;
- `reconciliation_required=true`;
- `dns_policy_applied=false`;
- `proxy_policy_applied=false`;
- `infrastructure_mutation_authorized=false`;
- `external_publication_authorized=false`.

Cozy UI wording is therefore «Семейные правила сохранены / Ожидают применения и проверки», never a false claim that filtering is active.

## Not included in this slice

- concrete production DNS/proxy enforcement adapter registration;
- production execution orchestration around the typed adapter boundary;
- final verification that may transition protected policy state to `enforcement_verified=true`;
- verified recovery completion after rollback read-back;
- production HTTP route wiring for enforcement;
- VPN egress policy (0.61, outside the current development boundary);
- RC/Public Stable promotion.

Any later 0.60 execution slice must preserve explicit adapter capability, exact Desired State binding, separate provider acceptance, Actual State post-condition verification, recovery and negative-security qualification. Provider command acceptance must never be interpreted as enforcement success.
