# Home Center 0.32.0

Status: development qualification candidate.

Home Center 0.32 adds batch exact-state revalidation for a complete module-admission
set previously bound to one canonical runtime compatibility snapshot. The
contract answers one bounded question: whether the whole `masb-*` evidence set is
still current for a fresh `mcs-*` runtime state.

## Admission-set revalidation

`home_center.module_admission_set_revalidation.revalidate_module_admission_set()`
accepts:

- the original canonical compatibility snapshot;
- the original `module-admission-snapshot-binding.v1`;
- the complete set of manifests, verified artifacts and exact admission
  decisions represented by that binding;
- one fresh canonical compatibility snapshot.

The original snapshot and binding are reconstructed before comparison. Missing,
extra, duplicated, malformed or tampered member evidence therefore fails closed
instead of being treated as a partial revalidation.

Each member is then passed through the existing exact
`revalidate_module_compatibility_decision()` boundary using the fresh snapshot.
This preserves manifest/artifact/provenance verification and recomputes current
compatibility rather than trusting a caller-supplied status.

## Set-level stale semantics

The result is `current` only when both conditions hold:

1. the fresh canonical runtime snapshot is identical to the original snapshot;
2. every member admission decision remains exact-current.

A Home Center version, architecture, operating-system, capability-set or
installed-module change makes the bound set stale. A module whose dependency,
conflict or compatibility result changes is reported individually, while the
single set result remains stale until a new exact admission set is evaluated and
bound.

The deterministic `masr-*` evidence records the original binding and snapshot,
the fresh snapshot, snapshot-level drift reasons, per-module original/fresh
decision identities, fresh compatibility status and the sorted set of stale
module IDs. Member ordering does not change the evidence identity.

## Safety boundary

The revalidation result is evidence only and fixes:

- `installation_authorized = false`;
- `execution_authorized = false`;
- `production_mutation_enabled = false`;
- `external_publication_authorized = false`.

It does not install modules, run lifecycle actions, create Jobs, mutate service
state, change infrastructure or publish external access.

## Contracts and tests

The candidate adds the closed
`home-center.module-admission-set-revalidation.v1` JSON Schema and targeted tests
for exact-current sets, deterministic ordering, Home Center version drift,
capability drift, dependency-induced compatibility blocking, incomplete set
rejection, tampered binding/snapshot rejection, deterministic `masr-*` identity
and the non-authorizing schema boundary.

Release identity is `0.32.0` across VERSION, Python package metadata and runtime
package metadata. No data migration is required because this package adds
side-effect-free compatibility evidence on top of the 0.29-0.31 admission line.

The 0.32 branch remains a development candidate until its complete qualification
and release gates pass.
