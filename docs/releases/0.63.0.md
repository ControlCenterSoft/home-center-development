# Home Center 0.63.0

Status: official release.

Release profile: `single-node-core`.

Home Center 0.63.0 adds bounded QR guest/device onboarding on top of Public Stable 0.62.1. The release keeps provider execution, infrastructure mutation, external publication, unqualified multi-node/HA and commercial-launch clearance outside the claimed Stable profile.

## User-visible result

A parent can issue a short-lived QR onboarding invitation for an existing guest or an exact registered unmanaged device. The invitation is single-use, revocable, expires automatically and is bound to the exact Household state. Invitation consumption remains distinct from the actual product effect. The product effect requires a second explicit parent confirmation, is admitted as one durable typed Job and becomes successful only after authoritative product-state read-back verifies the expected post-condition.

The release includes:

- guest or exact-device subject binding;
- 60–1800 second TTL;
- single-use onboarding code with only SHA-256 durable evidence;
- QR payload explicitly classified as a short-lived onboarding code, not an administrative credential;
- expiration, revocation and consumed-state enforcement;
- deterministic redemption plan and explicit confirmation;
- closed JSON contracts for QR domain/runtime/API/effect boundaries;
- exact Household `snapshot_id` / `resource_version` / `generation` binding;
- additive canonical StateStore migration for QR runtime and operation evidence without changing previously published migrations;
- transactionally guarded consume/revoke with exact version and idempotency evidence;
- authenticated same-origin issue/plan/consume/revoke HTTP routes using existing session, CSRF/origin, bounded-body and external-access fences;
- privacy-minimized receipt-only Audit persistence in the existing hash-chained StateStore Audit log;
- restart and backup/restore preservation of consumed/revoked terminal state and operation evidence without durable raw onboarding codes;
- exact effect handoff reconstructed server-side from one verified terminal QR receipt/runtime record;
- fail-closed handoff validation preventing guest-scope broadening, effect-kind relabeling, invented device identity and premature success claims;
- durable typed effect Job admission with exact current-Household revalidation, idempotency and Audit evidence;
- concrete bounded product-state effect adapters for supported QR effect Job classes;
- restart-safe effect worker semantics: `preflight` executes once, `verifying` performs read-back only, `running` is outcome-uncertain and never automatically reinvoked, terminal success is replay-safe;
- authoritative post-condition read-back before the Job can reach `succeeded`;
- transport-neutral explicit effect `admit` and `run` API contracts with a separate confirmation for each step;
- authenticated same-origin V11 HTTP routes for effect admission and run, restricted to an enabled Household parent and accepting only `invitation_id` or durable `job_id`, never a client-supplied handoff;
- reproducible artifact qualification, Public repository privacy boundary, Infrastructure neutrality and CodeQL security gates;
- commercial-engineering source validation confirming that the QR train adds no third-party runtime/distribution client dependency.

## Safety boundary

The QR payload must never contain a long-lived administrative credential, emergency-admin secret, directory administrator password or persistent API token. The short-lived onboarding code is single-use and is not persisted or logged as durable evidence.

Invitation issue/plan/consume/revoke does **not** by itself create or verify the product effect. The separate effect path requires explicit confirmation, reconstructs the effect from authoritative terminal state and admits a durable typed Job. Positive onboarding-effect success is returned only after exact authoritative read-back yields `post_condition_verified=true`.

Unknown, stale, ambiguous, tampered or outcome-uncertain state fails closed. A Job observed in `running` after interruption is never automatically re-executed. Replay of an already verified terminal Job returns the existing verified result without duplicating the effect.

The bounded QR product effect does not grant generic provider execution, infrastructure mutation or external publication authority. Concrete provider execution remains fail-closed unless separately qualified. HA/automatic failover is not claimed by this `single-node-core` release profile. Commercial-launch clearance remains a separate business/legal boundary and is not implied by Technical Public Stable qualification.

## Upgrade and rollback boundary

The supported release path is Home Center 0.62.1 → 0.63.0. Final promotion is permitted only for the exact release identity that passes deterministic artifact qualification, hosted and real-systemd install/upgrade/health/rollback qualification, state/configuration/admin-password preservation, CodeQL, privacy and infrastructure-neutrality checks. Published 0.62.1 artifacts and migrations remain immutable.

Technical Public Stable qualification must remain distinct from unqualified provider/HA/commercial-launch claims.
