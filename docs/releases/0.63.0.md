## Safety boundary

QR presentation and invitation consumption do **not** create an OS/directory account, register a new device, change `managed`, grant parent/admin privileges, execute a provider, mutate network infrastructure or publish a service externally. Revoked, expired, consumed, stale-Household or code-mismatched invitations fail closed.

The QR payload must never contain a long-lived administrative credential, emergency-admin secret, directory administrator password or persistent API token. The short-lived onboarding code is single-use and must not be persisted or logged as durable evidence. Durable QR receipts explicitly report `onboarding_effect_verified=false`; their positive post-condition applies only to the invitation-state transition itself.

Guest runtime issuance is intentionally narrower than the foundation contract: the current runtime accepts only an existing enabled `guest` member and `internet.guest` scope. Device runtime issuance accepts only an already registered unmanaged device bound to the exact target member. Effect handoff/admission cannot broaden either boundary.

The local effect adapter introduced by this source line mutates only bounded Home Center product state. It does not claim that a network, directory, MDM or other external provider has applied the effect. Provider execution, generic infrastructure mutation, managed-state mutation and external publication remain closed. A Job is not successful because an adapter accepted a command: the exact persisted product state must be read back and verified first.
