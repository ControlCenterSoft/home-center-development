# Home Center 0.64.0

Status: source-development package; not Release Candidate and not Public Stable.

## Planned product result

0.64 introduces explainable recommendations and a bounded safe auto-repair model. Home Center may only propose or later automate cases that are explicitly typed, policy-allowed, verifiable and recoverable. A command being accepted is never equivalent to a successful repair.

## Prepared source boundary

The current source preparation contains:

- exact content-addressed recommendation evidence and deterministic repair plans;
- confirmation-aware, exact-state safe-repair admission;
- `automation_candidate` classification for the bounded low-risk read-only compatibility refresh class without granting automatic execution;
- mandatory durable Job/Audit/post-condition/recovery requirements;
- exact-bound completion evidence with false-success prevention;
- bounded Cozy/Full repair history projection with verified-only `Исправлено` status;
- closed JSON Schema contracts and negative/security test source.

## Deliberate limits

This package does not add a repair executor, provider mutation adapter, infrastructure mutation authority, external publication, automatic policy/device mutation, new database migration, new public API route or new runtime dependency. `VERSION` remains unchanged until a later exact-candidate release step.

The first actual repair executor must be a separate qualified layer using the existing Identity/RBAC → Change/Job → typed execution → read-back → post-condition verification → Audit/recovery chain.

## Release gates still required later

Before 0.64 can become Release Candidate/Public Stable, the final integrated exact candidate must qualify the runtime executor boundaries that are actually enabled, persistence/restart/backup behavior, install/upgrade/rollback, security/privacy, artifact/release identity and the bounded commercial/legal release evidence required by the authoritative Roadmap.
