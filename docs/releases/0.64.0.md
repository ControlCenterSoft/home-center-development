# Home Center 0.64.0

Status: source preparation only; not Release Candidate and not Public Stable.

Authoritative Public Stable baseline for this work is Home Center 0.63.0.

## Scope

0.64 introduces the bounded foundation for Recommendations and safe auto-repair. Eligibility remains intentionally non-executing: it evaluates whether an exact repair candidate is eligible for a future automatic repair path under an explicit policy allowlist.

Eligibility requires a typed allowlisted action, exact Household/resource generation and content-addressed evidence, an explicit policy identity/digest, an allowed risk class, proven recovery semantics, a verifiable post-condition, and no provider execution, generic infrastructure mutation or external publication requirement.

The development line includes bounded durable recommendation history, stale-safe current-state admission revalidation and a transport-neutral typed repair Job lifecycle. Job identity is bound to exact admission/recommendation evidence plus SHA-256-only idempotency evidence. The lifecycle is `admitted → running → verifying → succeeded/failed`; ambiguous execution becomes `reconcile-required` and never receives automatic retry. An accepted effect receipt is not success: only separate verified post-condition evidence can produce `succeeded`. Job transition timestamps are monotonic; stale/out-of-order transition evidence fails closed instead of rewinding durable state.

The current source line additionally defines a closed action-specific adapter and authoritative read-back capability boundary. Adapter requests are bound to the exact Job, recommendation digest, Household/resource generation and source evidence. Unknown or duplicate adapters fail closed. Adapter acceptance always keeps `post_condition_verified=false`; read-back observations are `matched`, `mismatched` or `unknown`. No production adapter is registered by this boundary itself.

A separate fail-closed post-condition decision binds the exact verifying Job, recommendation digest, accepted effect receipt, Household/resource identity, resource generation and observation evidence. An adapter-labelled `matched` observation is not trusted in isolation: any Job/recommendation/result/target/generation mismatch blocks verification. A positive decision emits content-addressed verification evidence but still does not transition the durable Job or claim repair success.

The source line now also contains a restart-safe transport-neutral worker boundary. The worker durably moves an admitted Job to `running` before the first action-adapter invocation. If execution is interrupted after that point, a later invocation refuses to call the adapter again and reports an uncertain outcome instead of retrying. A durable `verifying` Job may resume authoritative read-back without a second action invocation. Only the exact-bound verification decision can feed the terminal Job transition; `unknown`, mismatched target/generation, failed execution and ambiguous execution remain fail-closed.

A bounded SQLite repair-Job repository is also prepared. It persists only the closed typed Job projection, stores SHA-256 idempotency evidence rather than raw idempotency keys, supports exact current state/timestamp compare-and-set, verifies persistence by read-back, survives process restart, and never persists generic execution/provider/infrastructure/publication authority. The adapter deliberately does not self-migrate: installation of its schema remains the responsibility of the canonical StateStore migration path.

The exact recommendation-history migration-5 SQL payload is now prepared as a dedicated product contract and is qualified against the existing history repository schema. It must remain the unique immediate successor of the current canonical StateStore migration set, match the repository schema byte-for-semantics, be idempotent, and create only the bounded recommendation-history table/index. Preparation does not install the schema; wiring migration 5 into canonical `StateStore` plus upgrade/backup/restart qualification remains the next integration gate.

## Safety boundary

`eligible_for_auto_repair=true` is evidence only. `admissible_for_job=true` is also bounded evidence; neither state grants mutation authority. Recommendation, history, admission, Job, adapter-request/result, read-back, verification-decision, persistence and worker contracts keep generic execution/provider/infrastructure/publication authority closed outside the exact action-specific adapter boundary.

Durable recommendation history stores no command, provider payload, credential or repair output. Raw idempotency keys are not part of the durable Job projection or persisted Job state. An interrupted or ambiguous repair is never re-invoked automatically or reported as successful without exact-bound verified read-back. A `running` Job after uncertain interruption is deliberately non-retryable; a `verifying` Job may repeat only the read-only authoritative observation.

The future production runtime must repeat authoritative state checks immediately before mutation, use only explicitly registered supported low-risk adapters, persist canonical Job/Audit/recovery evidence and expose the resulting exact-bound history without creating a parallel execution path.

## Commercial and security boundary

This foundation adds no third-party runtime dependency and no remote-service client dependency. It does not claim provider qualification, HA capability or commercial-launch/legal clearance. Those remain separate release/profile boundaries.

## Next required work

Before 0.64 can become a release candidate, subsequent slices must wire the prepared recommendation-history migration and repair Job schema into the canonical StateStore migration path and qualify upgrade/backup/restart preservation, connect admission and worker execution to authenticated/RBAC-gated product runtime, register only bounded supported low-risk action adapters, persist Audit/recovery evidence, expose understandable recommendation/repair history in UI, and complete exact 0.64 release identity/install/upgrade/security/packaging qualification.
