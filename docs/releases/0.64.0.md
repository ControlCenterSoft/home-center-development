# Home Center 0.64.0

Status: source preparation only; not Release Candidate and not Public Stable.

Authoritative Public Stable baseline for this work is Home Center 0.63.0.

## Scope

0.64 introduces the bounded foundation for Recommendations and safe auto-repair. Eligibility remains intentionally non-executing: it evaluates whether an exact repair candidate is eligible for a future automatic repair path under an explicit policy allowlist.

Eligibility requires a typed allowlisted action, exact Household/resource generation and content-addressed evidence, an explicit policy identity/digest, an allowed risk class, proven recovery semantics, a verifiable post-condition, and no provider execution, generic infrastructure mutation or external publication requirement.

The development line includes bounded durable recommendation history, stale-safe current-state admission revalidation and a transport-neutral typed repair Job lifecycle. Job identity is bound to exact admission/recommendation evidence plus SHA-256-only idempotency evidence. The lifecycle is `admitted → running → verifying → succeeded/failed`; ambiguous execution becomes `reconcile-required` and never receives automatic retry. An accepted effect receipt is not success: only separate verified post-condition evidence can produce `succeeded`.

The current source line additionally defines a closed action-specific adapter and authoritative read-back capability boundary. Adapter requests are bound to the exact Job, recommendation digest, Household/resource generation and source evidence. Unknown or duplicate adapters fail closed. Adapter acceptance always keeps `post_condition_verified=false`; read-back observations are `matched`, `mismatched` or `unknown`. No production adapter is registered by this boundary itself.

A separate fail-closed post-condition decision binds the exact verifying Job, recommendation digest, accepted effect receipt, Household/resource identity, resource generation and observation evidence. An adapter-labelled `matched` observation is not trusted in isolation: any Job/recommendation/result/target/generation mismatch blocks verification. A positive decision emits content-addressed verification evidence but still does not transition the durable Job or claim repair success.

## Safety boundary

`eligible_for_auto_repair=true` and `admissible_for_job=true` are bounded evidence states, not mutation authority. Recommendation, history, admission, Job, adapter-request/result, read-back and verification-decision contracts keep generic execution/provider/infrastructure/publication authority closed outside the exact action-specific worker boundary.

Durable recommendation history stores no command, provider payload, credential or repair output. Raw idempotency keys are not part of the durable Job projection. An interrupted or ambiguous repair must never be re-invoked automatically or reported as successful without exact-bound verified read-back.

The future production runtime must repeat authoritative state checks immediately before mutation, select an explicitly registered action-specific adapter, persist Job/Audit/recovery evidence and durably apply exact-bound post-condition evidence before user-visible success.

## Commercial and security boundary

This foundation adds no third-party runtime dependency and no remote-service client dependency. It does not claim provider qualification, HA capability or commercial-launch/legal clearance. Those remain separate release/profile boundaries.

## Next required work

Before 0.64 can become a release candidate, subsequent slices must install recommendation/history and Job state through canonical StateStore migration/persistence, connect admission and execution to authenticated/RBAC-gated product runtime, register only bounded supported low-risk action adapters, preserve/recover interrupted Job state without implicit reinvocation, durably transition the Job only from exact verification evidence, expose understandable recommendation/repair history in UI, and complete exact 0.64 release identity/install/upgrade/security/packaging qualification.
