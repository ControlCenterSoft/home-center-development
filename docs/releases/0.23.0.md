# Home Center 0.23.0

Status: official release.

Home Center 0.23 continues the cumulative home-service execution lifecycle from
the published 0.22 line and introduces the explicit boundary that can commit an
already validated service-state transition to durable state.

## Durable transition authorization

- The inert 0.22 transition decision and prepared commit remain non-mutating by themselves.
- A separate `home-service-transition-authorization.v1` contract must bind the exact commit, decision, instance generation and resource version before durable mutation is enabled.
- Missing, disabled or mismatched authorization fails closed before any service-instance state change.
- Authorization is intentionally single-purpose: it enables only the bound durable commit and carries no arbitrary command or secret value.

## Exact compare-and-swap commit

- `PreparedInstanceTransition` preserves the exact `next_generation` and `next_resource_version` produced by the validated transition commit instead of recomputing a different resource version at persistence time.
- The durable store keeps the existing compare-and-swap precondition and idempotency key semantics.
- An exact replay returns the previously committed result without applying the transition a second time.
- Current configuration revision and external-publication state are preserved across the state-only commit.

## Apply receipt

- Every successful apply or idempotent replay produces a deterministic `home-service-transition-apply-receipt.v1` evidence record.
- The receipt records the exact commit, authorization, resulting generation/resource version and whether this call performed the write or replayed it.
- A receipt never authorizes a subsequent mutation.

## Baseline guarantees

- Release identity is `0.23.0` across VERSION, package metadata, runtime metadata, and release notes.
- The release is based on the published `0.22.3` baseline and therefore retains the 0.22.1–0.22.3 web/deployment-profile compatibility fixes and deployment safeguards.
- Home Center 0.22.0 admission, worker-claim, execution-revalidation, result-evidence and transition-decision guarantees remain cumulative requirements.
- The durable mutation boundary is explicit and compare-and-swap guarded; publication of a build does not itself enable service operations.

## Release artifacts

The official distribution for this source release uses GitHub-generated source archives for the exact release tag (`tar.gz` and `zip`). No additional binary asset is required for the 0.23.0 source release.
