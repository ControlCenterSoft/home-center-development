# Home Center 0.23.0

Статус: опубликованный исходный релиз.

Home Center 0.23 продолжает накопительный жизненный цикл выполнения домашних сервисов из линии 0.22 и добавляет явную границу, которая может зафиксировать уже проверенный переход состояния сервиса в durable state.

## Durable transition authorization

- Неизменяющее состояние решение перехода и подготовленный commit остаются non-mutating сами по себе.
- Отдельный контракт `home-service-transition-authorization.v1` должен быть привязан к точному commit, decision, instance generation и resource version до разрешения durable mutation.
- Отсутствующая, отключённая или не совпадающая authorization отклоняется до изменения состояния экземпляра сервиса.
- Authorization имеет единственное назначение: разрешить только связанный durable commit и не содержит произвольных команд или значений секретов.

## Exact compare-and-swap commit

- `PreparedInstanceTransition` сохраняет точные `next_generation` и `next_resource_version`, сформированные проверенным transition commit.
- Durable store сохраняет compare-and-swap precondition и idempotency semantics.
- Точный повтор операции возвращает ранее зафиксированный результат без повторного изменения состояния.
- Текущая configuration revision и состояние external publication сохраняются при state-only commit.

## Apply receipt

- Каждый успешный apply или idempotent replay формирует детерминированный `home-service-transition-apply-receipt.v1` evidence record.
- Receipt фиксирует точный commit, authorization, итоговые generation/resource version и признак фактической записи либо replay.
- Receipt не разрешает последующую mutation.

## Накопительные гарантии

- Release identity — `0.23.0` в VERSION, package/runtime metadata и release notes.
- Версия основана на опубликованной линии `0.22.3` и сохраняет Web/deployment-profile compatibility fixes и deployment safeguards патчей `0.22.1`–`0.22.3`.
- Гарантии 0.22 по execution admission, worker claim, execution revalidation, result evidence и transition decision остаются обязательными.
- Новая durable mutation boundary является явной и защищена compare-and-swap; публикация исходного релиза сама по себе не включает произвольное выполнение сервисных операций.

Отдельный стабильный бинарный канал распространения может иметь более старую версию; перед установкой необходимо сверять версию и состав фактически опубликованного артефакта выбранного канала.
