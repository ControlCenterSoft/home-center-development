# Home Center 0.61.0

Status: official release.

Release profile: `single-node-core`.

## Назначение

Home Center 0.61.0 добавляет provider-neutral VPN egress policy foundation поверх официального Home Center 0.60.0 Public Stable. VPN не является обходным каналом: более строгий parental `DENY` всегда имеет абсолютный приоритет над VPN и direct egress.

## Что входит в релиз

- provider/version/location evidence с bounded reachability, latency и stability;
- deterministic provider/location selection без скрытой activation authority;
- full и split routing decision surface;
- explicit DNS strategy: `provider`, `parental` или `system`;
- kill-switch и fallback semantics с fail-closed contradiction checks;
- exact binding к composed Household policy и optional parental Internet policy;
- strict storage/transport reconstruction provider, policy, observation и route-decision evidence;
- Cozy и Full UI projections без execution authority;
- reproducible wheel и exact node deployment candidate обязаны содержать интегрированный 0.61 VPN runtime и закрытые JSON contracts.

## Safety boundary

Provider selection is not VPN activation. Provider observation является read-only evidence и не разрешает изменение routing, DNS, firewall или внешнего VPN provider.

В bounded `single-node-core` профиле 0.61.0 не заявляются concrete production VPN adapter execution и network/firewall/routing mutation. При отсутствии отдельно квалифицированного adapter соответствующая фактическая VPN activation capability остаётся fail-closed/disabled/unclaimed. Неоднозначный provider outcome не может автоматически повторяться и не считается успехом без обязательного post-condition read-back.

Parental filtering остаётся authoritative. VPN policy не может превратить `vpn_allowed=false` в true. При связанном parental policy более строгий `DENY` имеет абсолютный приоритет; system DNS не может ослабить parental DNS policy, а kill switch/fallback обязаны сохранять fail-closed semantics.

Multi-node HA / automatic failover также не заявляются без отдельной qualification. Отсутствие optional HA/provider claims не превращается в выдуманный PASS и не блокирует технически честный bounded Stable профиль.

## Install / upgrade / rollback

Release qualification использует точные immutable identities: официальный Public Stable `0.60.0` как baseline и exact `0.61.0` candidate без переписывания candidate source во время теста. Поддерживаемый переход 0.60.0 → 0.61.0 должен подтвердить install/upgrade, readiness, restart, сохранность пользовательского состояния и локальных credentials, а также rollback обратно к 0.60.0.

## Security и release evidence

Public Stable promotion допускается только после exact-head Home Center CI на Python 3.12/3.13/3.14, reproducible artifact qualification, CodeQL `security-extended` fail-closed current-source gate, Public repository privacy boundary, Infrastructure neutrality и полного immutable release artifact set с checksum/provenance/manifest/SBOM evidence.

False Success является release blocker: provider selection, observation или command acceptance не могут отображаться как подтверждённая VPN activation без post-condition evidence.

## Commercial / legal boundary

0.61.0 не добавляет concrete bundled VPN provider и не вводит новую provider-specific runtime dependency. Технический Public Stable не является automatic commercial launch clearance. Любой будущий concrete VPN provider требует отдельного license/source/distribution/notice/support evidence до provider-specific commercial claims.

## Совместимость

Home Center 0.61.0 остаётся полноценным local-first single-node продуктом. Не заявленные concrete provider execution, network mutation, HA и commercial-launch возможности остаются выключенными или неподтверждёнными и не расширяют полномочия релиза.
