# Home Center 0.49.0

Status: official release.

## Что изменилось

Home Center 0.49.0 развивает домашнюю модель поверх 0.48.0 и сохраняет безопасные границы текущего Stable. Основные изменения:

1. подтверждаемое добавление членов семьи с ролями `parent`, `child` и `guest` через Household API;
2. fail-closed проверка целостности snapshot/commit evidence для Household;
3. агрегированная проверка совместимости модулей сразу с несколькими Home Services и повторная проверка при изменении исходного состояния.

Изменения не дают модулю, пользователю или UI неявных полномочий на системные, сетевые или внешние изменения.

## Семья и подтверждение изменений

Добавление человека выполняется в два этапа: сначала Home Center формирует предложение изменения, затем пользователь отдельно подтверждает его. Предложение связано с точными `snapshot_id`, `resource_version` и generation состояния семьи. Если состояние изменилось, подтверждение отклоняется как устаревшее без мутации данных.

Сервер самостоятельно определяет действующего члена семьи по аутентифицированной учётной записи. Клиент не может подменить actor/member identity. Повтор уже завершённого подтверждения идемпотентно возвращает существующий результат и не создаёт дубликат.

Snapshot и commit evidence проверяются на соответствие каноническому содержимому и допустимому переходу поколений. Подделанные или внутренне противоречивые значения отклоняются fail-closed.

## Совместимость модулей с несколькими Home Services

Контур aggregate compatibility собирает совместимость модуля с набором Home Services и позволяет повторно подтвердить её для фактического текущего состояния. Drift определяется по identity набора требований, версии Home Center, модулю и его версии, набору сервисов, per-service evidence, blocked-service set и итоговому статусу совместимости.

Compatibility evidence остаётся только доказательством проверки. Оно само по себе не разрешает admission, installation, execution, production mutation или внешнюю публикацию.

## Security and commercial boundary

Релиз сохраняет обязательную аутентификацию, принудительную смену первоначального пароля администратора, серверную привязку actor/member, optimistic stale-state protection, audit evidence, infrastructure neutrality и default-deny для внешней публикации.

Операции Household ограничены внутренним product-state Home Center. Они не создают системные или доменные учётные записи, не изменяют профили, DNS, VPN, MDM, устройства, Desired State, NAT/port-forwarding и не вызывают provider execution без отдельной разрешённой операции.

Коммерческие и юридические границы текущего Stable сохраняются: новый функционал не обходит существующие проверки лицензирования, юридической допустимости и release/commercial gates. Исторические официальные релизы и их identity не изменяются.

## Обновление

Обновление выполняется штатным Stable-механизмом Home Center с проверкой release identity и артефактов. Для двухузлового кластера применяется rolling-порядок: сначала peer-узел, проверка его здоровья и репликации, затем coordinator. При ошибке переход на следующий узел запрещён до безопасного восстановления или rollback.

Пользовательские данные, настройки и заданный пароль администратора при штатном обновлении сохраняются.

## Release qualification

Для точного релизного дерева 0.49.0 обязательны:

- Python 3.12 и 3.13;
- компиляция и полная тестовая выборка;
- валидация JSON contracts;
- детерминированная и воспроизводимая сборка wheel;
- release-artifact identity и обязательный состав runtime;
- public repository privacy boundary;
- infrastructure-neutrality checks;
- отсутствие блокирующих security/release findings.

Официальный релиз допускается к публикации только после зелёного результата обязательных детерминированных gates на точном финальном commit. Внешние дополнительные review не заменяют эти проверки.
