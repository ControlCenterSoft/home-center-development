# Home Center 0.48.0

Status: official release.

Home Center 0.48 connects the mobile-first «Уютный» interface to authenticated, audited Household product state while keeping provider and infrastructure mutation disabled. It also restores the complete session/login and mandatory first-password-change flow in the current UI line before Household actions are made available.

## Authenticated Cozy workspace

- The Web UI checks the current session before exposing Home Center state.
- Local administrator and enabled AD authentication providers remain supported by the existing API.
- A local administrator still must change the default password before normal product use.
- «Уютный» / «Полный» switching is available only inside the authenticated workspace.
- Logout terminates the server session and returns to the login view.

## Household bootstrap

`POST /api/v1/household/bootstrap` creates the first Household product-state snapshot from one human-readable parent display name.

The server, not the browser, creates the internal member identifier and binds the currently authenticated actor to that parent. The Household snapshot and actor binding are written as one SQLite-backed metadata value so the first administrative binding cannot be separated from its snapshot by a partial runtime write.

Bootstrap is create-once. A second bootstrap request fails closed.

## Household status and planning

- `GET /api/v1/household` returns the validated current Household snapshot or an explicit `configured=false` state.
- `POST /api/v1/household/intents/plan` builds exact-state Household/Intent proposal evidence for the authenticated actor binding.
- The actor member identity is derived server-side; a request cannot claim another parent member id.
- An authenticated actor without a Household binding cannot plan an administrative household intent.
- Persisted snapshot identity/resource-version evidence is recomputed on read and fails closed if tampered.

## Safety boundary

0.48 mutates Home Center Household product state only. It does **not**:

- create operating-system or directory accounts;
- change DNS, internet policy, VPN or MDM;
- enroll physical devices;
- execute provider commands;
- modify external Desired State;
- enable NAT, port-forwarding or external publication.

Household/Intent proposals remain confirmation-required evidence with `mutation_authorized=false`, `infrastructure_mutation_authorized=false` and `external_publication_authorized=false`.

## Security and commercial boundary

The 0.48 scope adds no third-party runtime dependency and no new distribution mode. It introduces no new license payload. Existing authentication, RBAC, audit, recovery, bootstrap-password and external-publication controls remain authoritative. Household actor/member binding is server-side and persisted Household evidence is integrity-checked before use.

## User-visible result

In «Уютный» → «Семья», an unconfigured installation asks only for the first parent's name. After bootstrap the persisted parent card is rendered from the Household API. The next release boundary enables confirmation-gated member addition on top of the exact snapshot/resource-version contract.
