# Home Center 0.57.0

Status: official release.

## Профиль релиза

Home Center 0.57.0 публикуется как технический PUBLIC STABLE в профиле `single-node-core`. Single-node остаётся полноценным поддерживаемым режимом Home Center.

Этот профиль намеренно **не заявляет** неподтверждённые возможности:

- multi-node HA / automatic failover — не заявлены как поддержанные в 0.57.0;
- concrete provider execution — не заявлен как production-supported без отдельно квалифицированного adapter;
- commercial launch clearance — не заявлен и остаётся отдельным коммерческим контуром.

Отсутствие этих claims не превращается в фиктивный PASS: соответствующие возможности остаются fail-closed, disabled или явно unclaimed.

## Основной пользовательский результат

0.57.0 добавляет безопасную типизированную границу выполнения подключения домашнего устройства через выбранного provider управления устройствами. После подтверждённого выбора provider из 0.56.0 доступны отдельные операции планирования и управления execution lifecycle:

- `POST /api/v1/household/devices/enrollment/execution/plan`;
- `POST /api/v1/household/devices/enrollment/execution/start`;
- `POST /api/v1/household/devices/enrollment/execution/cancel`;
- `POST /api/v1/household/devices/enrollment/execution/retry`.

Production provider execution в опубликованном `single-node-core` профиле не активируется автоматически. Без deliberately registered qualified adapter команда execution завершается fail-closed.

## Безопасность выполнения

- первый provider call требует отдельного явного подтверждения;
- в adapter передаются только ссылки `secret://...`, а не значения паролей, токенов и других секретов;
- start/cancel/retry фиксируются через durable Job и Audit;
- повтор того же запроса идемпотентен и не должен повторно отправлять provider-команду;
- retry разрешён только при доказанном безопасном исходе предыдущей попытки;
- timeout и неоднозначная transport error не считаются безопасными для автоматического retry;
- cancel считается принятым только после корректного типизированного provider response;
- незарегистрированный, неполный или неквалифицированный adapter отклоняется до начала production execution.

Provider command acceptance **не означает** успешный enrollment. В 0.57.0 сохраняются обязательные границы:

- `enrollment_completed = false`;
- `post_condition_verified = false`;
- `managed_state_change_authorized = false`;
- policy application не разрешается только фактом provider acceptance;
- infrastructure mutation и external publication не разрешаются этой границей.

Состояние `managed=true` допустимо только после отдельной последующей post-condition verification фактического результата подключения.

## Upgrade / rollback / сохранность состояния

Поддерживаемый путь 0.56.0 → 0.57.0 квалифицируется как точная release identity с проверкой install/upgrade, service readiness, сохранности пользовательского состояния и rollback обратно к 0.56.0.

Обновление не должно сбрасывать:

- Home Center configuration;
- SQLite state;
- установленный пользователем пароль локального `admin`;
- session/audit state;
- deployment profile и применимые service/timer states.

False Success запрещён: успешный запуск installer или provider command сам по себе не является подтверждением результата.

## Release qualification

PUBLIC STABLE promotion допускается только для одной exact immutable release identity. Для `single-node-core` обязательны:

- exact-head Home Center CI и exact source identity;
- reproducible artifact qualification;
- CodeQL `security-extended` с fail-closed medium-or-higher gate;
- Public repository privacy boundary;
- Infrastructure neutrality;
- upgrade, rollback и user-state preservation;
- real target-node install/upgrade, readiness, user-state preservation и rollback evidence, привязанное к exact release artifact;
- source/deployment artifact SHA-256 identities;
- checksum sidecar и `SHA256SUMS`;
- qualification/acceptance/release manifests;
- public provenance;
- SPDX SBOM.

Финальная публикация разрешается только после успешной exact-identity qualification. Никакой hosted rerun не подменяет фактическое target-node evidence.

## Явно не заявленные возможности

0.57.0 `single-node-core` не является доказательством multi-node HA, production provider adapter qualification или commercial/legal clearance. Эти возможности получают собственные qualification/activation tracks и не могут наследовать PASS от технического Stable профиля.

## Совместимость и дальнейшее развитие

0.57.0 продолжает Public Stable 0.56.0 и сохраняет local-first, infrastructure-neutral модель Home Center. Следующие версии могут добавлять post-condition verification, de-enrollment, policy enforcement и расширенные HA/provider profiles только после собственных release gates и без ослабления fail-closed semantics 0.57.0.
