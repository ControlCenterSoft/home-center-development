# Home Center 0.54.0

Status: source package prepared for qualification.

## Область релиза

Home Center 0.54.0 добавляет следующий ограниченный шаг «Уютный → Семья» после подтверждённого намерения подключить управление устройством: поиск доступных доверенных способов управления и формирование плана разрешения провайдера.

Релиз вводит локальный доверенный каталог провайдеров управления устройствами. По умолчанию каталог пуст. Home Center не считает провайдер доступным неявно и не поставляет фиктивные или placeholder-провайдеры. Провайдер попадает в кандидаты только если он присутствует в доверенном локальном реестре, имеет `ready=true` и явно поддерживает заявленную платформу устройства.

## Каталог провайдеров

Каталог закрытый и детерминированный. Профиль содержит:

- стабильный `provider_id` и отображаемое имя;
- явно поддерживаемые платформы;
- поддерживаемые режимы подключения;
- признак готовности.

Публичный Household API в 0.54 работает с каталогом только на чтение/планирование. В «Уютном» и публичном API нет метода, позволяющего создать произвольный провайдер, передать его credentials или самостоятельно выставить ему `ready=true`.

Отсутствие каталога считается корректным пустым состоянием. Повреждённое или невалидное сохранённое состояние каталога отклоняется fail-closed и не трактуется как доказательство доступности провайдера.

## Разрешение провайдера

План разрешения создаётся только после подтверждённого enrollment proposal из 0.53 и повторно проверяет это предложение относительно точного текущего Household snapshot.

Платформа устройства вводится пользователем как подсказка и фиксируется как:

- `platform_claim_source=user`;
- `platform_verified=false`.

Пользовательская подсказка не представляется как автоматически подтверждённый факт об устройстве.

Возможные состояния:

- `unavailable` — нет готового доверенного провайдера для заявленной платформы;
- `single-candidate` — найден ровно один готовый доверенный провайдер;
- `choice-required` — найдено несколько готовых доверенных провайдеров.

Даже при единственном кандидате Home Center не выбирает его автоматически. Любой план фиксирует `provider_selection_required=true` и `selected_provider_id=null`.

## Граница безопасности

План разрешения и каждый кандидат не дают разрешения на выполнение действий. План фиксирует:

- `provider_execution_authorized=false`;
- `policy_application_authorized=false`;
- `managed_state_change_authorized=false`;
- `infrastructure_mutation_authorized=false`;
- `external_publication_authorized=false`.

Каждый кандидат дополнительно содержит `execution_authorized=false`.

0.54 не выбирает провайдера, не создаёт enrollment token, не читает и не записывает credentials провайдера, не выполняет enrollment, не устанавливает MDM-профили, не применяет DNS/VPN/Wi‑Fi/firewall/filtering policy, не меняет флаг `managed` у Household device, не изменяет внешний Desired State и не публикует сервисы наружу.

## API

Добавляется аутентифицированный same-origin endpoint:

`POST /api/v1/household/devices/enrollment/provider-resolution/plan`

Request schema: `home-center.device-management-provider-resolution-request.v1`.

Запрос содержит только идентификатор подтверждённого enrollment proposal и выбранную пользователем платформу устройства. Запрос не принимает selected provider id, credentials или флаги разрешения выполнения.

Endpoint выбора провайдера или выполнения действий провайдера в 0.54 отсутствует.

## Интерфейс «Уютный»

После успешного подтверждения enrollment интерфейс предлагает действие «Найти способ управления». Пользователь явно выбирает тип устройства и запускает только безопасное планирование.

Интерфейс fail-closed проверяет, что:

- платформа остаётся неподтверждённым пользовательским вводом;
- выбор провайдера всё ещё обязателен;
- `selected_provider_id` равен `null`;
- все флаги execution/policy/managed-state/infrastructure/publication остаются `false`;
- каждый кандидат остаётся non-authorizing.

Для пустого каталога интерфейс сообщает, что доступного способа управления пока нет и ничего установлено не будет. Один кандидат показывается как найденный, но не выбранный. Несколько кандидатов отображаются только как варианты для будущего отдельного шага выбора.

## Qualification boundary

Qualification 0.54 должна быть кумулятивной поверх подтверждённых границ Household/member/device/management/enrollment релизов до 0.53 включительно. Release wheel должен содержать `device_management_provider.py` и `device_management_provider_runtime.py` вместе с предыдущими runtime boundaries.

Обязательные проверки 0.54:

- каталог по умолчанию пуст и не мутирует production-state;
- malformed catalog отклоняется fail-closed;
- кандидатами становятся только `ready=true` записи поддерживаемой платформы;
- confirmed enrollment обязателен;
- stale Household snapshot отклоняется;
- запрос не принимает selected provider id и credentials;
- один кандидат не выбирается автоматически;
- все execution/policy/managed-state/infrastructure/publication flags остаются false;
- «Уютный» интерфейс проверяет эти границы до отображения результата.

Persistent migration Household-state не требуется.
