# Home Center 0.28.0

Status: development qualification candidate.

Home Center 0.28 continues the versioned Household state boundary from 0.27 by
binding each side-effect-free Household/Intent proposal to one exact persisted
household snapshot. The package closes stale-plan ambiguity without adding any
provider execution, infrastructure mutation, external publication, Jobs, or
cluster behavior.

## Exact-state Household/Intent proposal

`home_center.household_intent_proposal` adds deterministic
`HouseholdIntentProposal` evidence. A proposal binds:

- the exact `household_id`;
- `snapshot_id`, `resource_version`, and `generation`;
- the complete validated Household intent;
- the deterministic Household intent plan;
- the actor's effective-policy identity.

The proposal ID is derived from those exact inputs. Rebuilding a proposal from
the same snapshot and intent therefore yields identical evidence.

## Stale-state and evidence revalidation

`revalidate_household_intent_proposal()` is side-effect free and fails closed.

A proposal is rejected as stale when the current Household snapshot differs by
household identity, snapshot identity, resource version, or generation. If the
state is still exact but the embedded intent, plan, policy identity, or proposal
identity no longer matches a fresh deterministic reconstruction, the proposal is
rejected as an evidence mismatch.

This means a Household change after planning invalidates the previous proposal
instead of allowing an old plan to be treated as current authorization.

## Safety boundary

Every proposal fixes:

- `confirmation_required = true`;
- `mutation_authorized = false`;
- `infrastructure_mutation_authorized = false`;
- `external_publication_authorized = false`.

The proposal can therefore be used as exact-state planning evidence only. It
does not create accounts, enroll devices, change RBAC, alter DNS/VPN/MDM,
publish services externally, or execute provider commands.

## Contracts and tests

A closed JSON Schema is added for `home-center.household-intent-proposal.v1`.
Targeted unit tests cover deterministic exact-snapshot binding, successful
same-state revalidation, stale invalidation after Household replacement,
cross-household rejection, and fail-closed detection of same-state evidence
tampering.

Release identity is `0.28.0` across VERSION, Python package metadata, and runtime
package metadata. No data migration is required because this candidate adds an
evidence contract over the 0.27 Household persistence boundary and does not
change the durable Household snapshot format.

The 0.28 branch remains a development candidate until its complete qualification
and release gates pass.
