# Home Center 0.30.0

Status: development qualification candidate.

Home Center 0.30 adds exact-state revalidation for the compatibility-aware
module admission decision introduced in 0.29. The package can prove whether one
previously produced admission decision still describes the current Home Center
runtime compatibility context without installing or executing the module.

## Exact-state admission revalidation

`home_center.module_admission_revalidation.revalidate_module_compatibility_decision()`
accepts:

- the exact Module Manifest v2 document;
- the matching `VerifiedModuleArtifact`;
- one previous `home-center.module-admission-decision.v1`;
- a fresh bounded Home Center runtime compatibility snapshot.

Before any comparison, the previous decision is reconstructed from its own
recorded runtime inputs through the 0.29 admission evaluator. Every serialized
field, decision identity and non-authorizing flag must match that reconstruction.
A modified, cross-artifact or otherwise inconsistent previous decision is
rejected as invalid evidence instead of being treated as a normal stale result.

## Fresh runtime snapshot

The fresh evaluation reuses the same fail-closed 0.29 admission rules and binds:

- Home Center semantic version;
- architecture and operating-system identifiers;
- available capability identifiers;
- installed module IDs and exact semantic versions.

Input collections are normalized by the admission evaluator, so ordering alone
does not create false drift.

The revalidation result is `current` only when the exact runtime snapshot and
compatibility result still reproduce the original decision. Otherwise it is
`stale` and records bounded drift reasons for version, platform, capability-set,
installed-module, compatibility-status or compatibility-reason changes.

A runtime change that remains technically compatible still invalidates the old
exact-state decision. Callers therefore cannot treat a previously compatible
result as permanently valid after the product version or module environment
changes.

## Safety boundary

`home-center.module-admission-revalidation.v1` is evidence only. Every result
fixes:

- `installation_authorized = false`;
- `execution_authorized = false`;
- `production_mutation_enabled = false`;
- `external_publication_authorized = false`.

Neither `current` nor `stale` authorizes module installation, lifecycle actions,
provider execution, network changes, service mutation or publication.

## Contracts and tests

A closed JSON Schema is added for the deterministic revalidation record.
Targeted tests cover exact-current replay, order normalization, harmless
capability/version changes, dependency drift that changes compatibility,
tampered prior evidence, authority-flag tampering, invalid fresh runtime
evidence, deterministic revalidation identity and the non-authorizing schema
constants.

Release identity is `0.30.0` across VERSION, Python package metadata and runtime
package metadata. No data migration is required: this candidate adds a
side-effect-free compatibility evidence contract over the 0.29 admission model.

The 0.30 branch remains a development candidate until its complete qualification
and release gates pass.
