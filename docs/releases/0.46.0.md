# Home Center 0.46.0

Status: development candidate

## Scope

Home Center 0.46.0 introduces the first product-level interface boundary between the mobile-first **«Уютный»** mode and the professional **«Полный»** mode without creating a second product or a separate execution path.

The release is limited to the 0.46 roadmap scope. It does not implement the 0.47 navigation model or the authenticated Household workspace assigned to 0.48.

## Interface modes

The web shell exposes a permanent two-mode switch:

- **«Уютный»** is the default presentation for ordinary home use;
- **«Полный»** preserves the infrastructure-oriented view;
- the selected mode is stored only in browser-local UI state and restored on the next opening;
- switching modes changes presentation only and does not mutate Desired State, permissions, infrastructure, provider state or external publication.

Keyboard left/right switching and explicit tab/tabpanel semantics are included so the selector remains usable without pointer-only interaction.

## «Домой» in Cozy mode

The mobile-first «Домой» screen is built from the existing read-only infrastructure state and presents:

- overall home status;
- number of discovered servers;
- number of available capabilities;
- understandable setup, degraded/unknown and offline states;
- a direct path to the full interface for technical diagnostics.

Unknown or missing node status is fail-safe and is never displayed as healthy. Only explicitly healthy/ready/online/managed node states contribute to the «Всё хорошо» summary.

## Full mode compatibility

The infrastructure-oriented node and capability view remains available in the same application. No existing execution API is replaced by the Cozy shell.

The Cozy shell performs only a read-only request to `/api/v1/infrastructure`. It introduces no POST/PUT/PATCH/DELETE path, no hidden mutation authority and no automatic network, NAT or external-publication behavior.

## Release identity

Release identity is `0.46.0` across `VERSION`, Python runtime metadata and package metadata.

No persistent-state migration is required.

## Security and commercial boundary

This release adds no third-party runtime component or new distribution mode. It therefore introduces no new license payload. Authentication, RBAC, audit, recovery and bootstrap-password rules remain unchanged.

The candidate remains development-only until the runner-based qualification flow validates the exact prepared head. This non-runner work does not claim CI, security-gate or release qualification success.
