# Home Center 0.50.0

Статус: кандидат разработки, не Public Stable.

## Назначение

Home Center 0.50.0 добавляет каноническую read-only проекцию фактического состояния совместимости модуля с требуемыми Home Services.

Контракт `home-center.module-home-service-compatibility-state.v1` связывает точное агрегированное compatibility evidence с результатом его exact-state revalidation и выдаёт один проверяемый снимок для API и интерфейса.

Проекция содержит:

- канонический `state_id`;
- content-derived `resource_version`;
- strong `ETag`;
- точную идентичность Home Center, модуля и его версии;
- исходную и свежую compatibility identity;
- перечень Home Services и заблокированных сервисов;
- наблюдаемый статус `compatible` / `blocked`;
- эффективный статус `compatible` / `blocked` / `stale`;
- причины drift при устаревшем evidence.

Если revalidation имеет статус `stale`, эффективный статус всегда становится `stale`, даже если свежая проверка отдельно показывает `compatible`. Это исключает ложное отображение устаревшего evidence как безопасно пригодного к использованию.

## Граница безопасности

Эта версия добавляет только read-only evidence projection. Она не предоставляет полномочий на admission, установку, execution, изменение production state или external publication.

Все authority flags в контракте обязаны оставаться `false`. Состояние не создаёт Jobs, не выполняет команды, не изменяет сетевую конфигурацию, не устанавливает Home Services и не меняет состояние Household.

Контракт остаётся infrastructure-neutral и не содержит привязки к конкретным именам серверов, IP-адресам, доменам или домашней топологии.

## Fail-closed свойства

Сериализованное состояние является закрытым и каноническим. Валидация отклоняет:

- неизвестные поля;
- некорректные или подменённые identity;
- некорректный `resource_version` или `ETag`;
- несовместимое сочетание freshness и effective status;
- некорректный blocked-service set;
- неканонический порядок сервисов;
- неизвестные drift reasons;
- любую попытку установить authority flag в `true`.

## Совместимость и миграция

Изменение не требует миграции persistent state. Оно использует уже существующие compatibility/revalidation evidence и добавляет поверх них детерминированную read-only модель для последующего API/UI потребления.

Перед публикацией версии должны быть подтверждены все обязательные qualification, security, commercial и release gates для точной release identity.
