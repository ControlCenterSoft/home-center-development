# Home Center 0.50.0

Status: official release.

## Назначение

Home Center 0.50.0 добавляет каноническую read-only проекцию фактического состояния совместимости модуля с требуемыми Home Services.

Контракт `home-center.module-home-service-compatibility-state.v1` связывает точное агрегированное compatibility evidence с результатом exact-state revalidation и выдаёт один проверяемый снимок для API и интерфейса.

Проекция содержит канонический `state_id`, content-derived `resource_version`, strong `ETag`, точную идентичность Home Center/модуля/версии, исходную и свежую compatibility identity, перечни сервисов и блокировок, наблюдаемый и эффективный статус, а также причины drift.

Если revalidation имеет статус `stale`, эффективный статус всегда становится `stale`, даже если свежая проверка отдельно показывает `compatible`. Это исключает ложное отображение устаревшего evidence как безопасно пригодного к использованию.

## Безопасность и коммерческая граница

Версия добавляет только read-only evidence projection. Она не предоставляет полномочий на admission, установку, execution, изменение production state или external publication. Все authority flags в контракте обязаны оставаться `false`.

Контракт остаётся fail-closed и infrastructure-neutral: неизвестные поля, подмена identity, некорректные resource version/ETag, несовместимые freshness/effective status, неканонические наборы сервисов и неизвестные drift reasons отклоняются.

0.50.0 не добавляет новый сторонний компонент или новый способ распространения. Существующие module legal/commercial compliance gates сохраняются без ослабления; этот read-only слой не создаёт самостоятельного коммерческого разрешения для модуля.

## Stable update boundary

Релиз наследует security hotfix 0.49.1: автоматический updater и его installer по умолчанию используют только `ControlCenterSoft/home-center-stable`. `home-center-development/releases` не является допустимым default update channel. Эта граница закреплена regression tests и должна оставаться fail-closed.

## Установка и обновление

Переход с 0.49.1 на 0.50.0 не требует миграции persistent state. Пользовательские данные, локальная конфигурация и установленный пароль администратора не должны сбрасываться.

Для HA сохраняется rolling-порядок peer/standby first → health/identity checks → coordinator. При ошибке переход ко второму узлу запрещён, а неуспешный artifact digest должен быть quarantined согласно существующему updater contract.

## Квалификация релиза

Exact source revision 0.50.0 обязан пройти GitHub-hosted CI на Python 3.12/3.13, полный pytest, reproducible wheel qualification, public-repository privacy boundary и infrastructure-neutrality. Публикация official source release и Public Stable promotion выполняются только для той же квалифицированной release identity.
