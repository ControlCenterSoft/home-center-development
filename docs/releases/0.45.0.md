# Home Center 0.45.0

Статус: официальный source release и текущий Public Stable.

## Состав релиза

Home Center 0.45.0 добавляет каноническую multi-service requirement-set boundary: один модуль может детерминированно требовать несколько Home Services, не получая полномочий на установку или execution.

`home-center.module-home-service-contract-multi-requirement-set.v1` объединяет существующие точные single-service requirement sets `mhscr-*` в один детерминированный evidence-объект `mhsmr-*`. Aggregate сохраняет identity каждого сервиса, точную identity его single-service requirement set и точные versioned Home Service/API contracts.

Порядок входных данных не влияет на identity: service requirements канонизируются по идентификатору сервиса. Дубли требований, смешанные Home Center/module contexts, повреждённые nested identities, неканонический порядок сериализации, неоднозначные mapping-типы и evidence с authority-bearing признаками отклоняются fail-closed. Lazy aggregate ограничен 64 наборами требований; ошибки итератора нормализуются в стабильный rejection code.

## Граница безопасности

Aggregate является только evidence. Он никогда не разрешает admission, установку, execution, production mutation или external publication.

Контракт topology-neutral и infrastructure-neutral. Он не добавляет Jobs/Operations behavior, Cluster/HA orchestration, placement semantics или скрытый release-promotion path. Существующая политика аутентификации не меняется.

Миграция постоянного состояния не требуется.

## Security и commercial boundary

Сериализованный контракт закрыт (`additionalProperties: false`), authority flags зафиксированы в `false`, вложенные exact identities повторно строятся и проверяются, а канонический порядок контролируется до принятия aggregate identity.

Версия не добавляет новый сторонний компонент или новый distribution mode. Поэтому новый license payload не вводится; существующее legal/compliance evidence модулей и сервисов остаётся authoritative для соответствующих компонентов.

## Проверка релиза

Точная release identity должна пройти обязательные qualification gates, включая проверки контрактов, воспроизводимости артефактов, public-repository privacy boundary и infrastructure-neutrality до публикации. Публикация версии сама по себе не предоставляет production mutation authority; установка и активация выполняются только через штатный проверяемый update path.
