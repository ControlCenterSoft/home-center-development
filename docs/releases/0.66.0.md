# Home Center 0.66.0

Status: source preparation only; not Release Candidate and not Public Stable.

Authoritative Public Stable baseline is Home Center 0.63.0. The nearer 0.64 and 0.65 release trains must complete their own release cycles independently; this branch is preparation within the three-release Roadmap horizon only.

## Scope of this source slice

0.66 begins the Smart Home device lifecycle milestone with:

- protected device Desired State for name, room, expected capabilities and optional configuration digest;
- read-only lifecycle projection over exact content-addressed ZigBee/MQTT inventory evidence;
- explicit `current` / `stale` / `unavailable` health semantics;
- explicit `in-sync` / `drifted` / `unknown` drift semantics;
- room/capability drift detection without false Healthy/Success;
- configuration verification kept unavailable until a typed provider read-back exists;
- deterministic plan-only rename and room-assignment changes bound to exact inventory SHA-256 and Desired State generation;
- mandatory explicit confirmation flag without granting execution authority;
- closed Draft 2020-12 schemas and negative test preparation.

## Safety boundary

This slice does not rename or move a device, call a provider, restore configuration, change infrastructure, publish externally or modify coordinator state. Stale/unavailable evidence produces `drift_state=unknown`, never `in-sync`.

A change plan is evidence for review only. A later execution path must repeat Identity/RBAC and exact-state revalidation, create a durable Change/Job, perform only a typed provider operation, then read authoritative Actual State back and verify the post-condition before showing success.

## Recovery / HA boundary

0.65 backup/recovery evidence remains a prerequisite for future configuration-recovery work where applicable, but backup existence does not authorize restore and does not prove recovery. A physical USB/serial coordinator remains a single physical dependency; this 0.66 slice makes no HA or automatic-failover claim.

## Security / commercial boundary

No third-party runtime dependency or remote-service dependency is added by this slice. No credential values, provider payloads or raw configuration are added to public contracts. Provider qualification, external-publication readiness, commercial/legal launch clearance and HA certification remain separate evidence domains.

## Remaining work before promotion

Full 0.66 still requires provider-specific health/diagnostics evidence; authenticated/RBAC-gated lifecycle execution; durable Change/Job/Audit and idempotency; authoritative post-condition verification; configuration restore execution and recovery verification; restart-safe reconciliation; Cozy/Full UI integration; persistence/backup/restore integration; supported install/upgrade/rollback tests; security/privacy qualification; reproducible packaging and the complete Public Stable promotion cycle.
