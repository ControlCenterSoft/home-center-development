# Home Center 0.59.0

Status: official release.

## Профиль релиза

Home Center 0.59.0 — bounded technical release поверх официального Public Stable 0.58.0. Релиз добавляет Policy Composer и защищённый policy lifecycle для Household: Desired State, read-only Actual State reconciliation, effective-state projection и confirmation-gated enforcement boundary с обязательной последующей проверкой результата.

Заявленный технический профиль — `single-node-core`. Multi-node HA / automatic failover, universal production policy backend и commercial launch clearance не заявляются как квалифицированные возможности 0.59.0 без отдельного exact-bound evidence. Отсутствующие optional capabilities остаются fail-closed, disabled или unclaimed и не подменяются фиктивным PASS.

## Что добавлено

- deterministic PolicyBundle/ComposedPolicy с anti-escalation правилами: policy может только ужесточать разрешённые role boundaries и не может включать запрещённые capability;
- exact Household/member/actor/Desired State binding для plan → explicit confirm → durable Job/Audit;
- protected policy Desired State с monotonic generation, stale-state rejection и idempotent replay;
- read-only policy Actual State reconciliation через deliberately registered read-only backend adapter;
- authenticated effective-state projection для «Уютного» и «Полного» интерфейсов без ложных enforcement claims;
- protected verified-policy state и reconciliation→verified transition только после свежего exact-bound evidence и повторной server-side authority/Desired State revalidation;
- confirmation-gated policy-enforcement plan/confirm/execute boundary с exact backend identity/version/capability evidence;
- backend mutation допускается только через deliberately registered mutation-capable adapter, прошедший exact qualification binding;
- backend acceptance не является enforcement success: после mutation требуется отдельный read-back/reconciliation/post-condition verification;
- automatic retry/reinvocation после неоднозначного backend outcome не разрешён;
- backup/restore сохраняет protected Desired State, Jobs, Audit, reconciliation/verification evidence;
- node deployment artifact и reproducible Python wheel обязаны содержать полный inherited 0.58 runtime и весь текущий 0.59 policy/enforcement/reconciliation/verification runtime, contracts и UI boundary.

## False-success и authority boundary

Policy plan, confirmation, Job creation или backend command acceptance сами по себе не означают, что policy фактически применена. Unknown, ambiguous, stale, future-dated, tampered или binding-mismatched evidence работает fail-closed. Verified state допускается только после exact post-condition evidence.

0.59.0 не создаёт generic shell/command API, не выдаёт неявную infrastructure/network/filesystem mutation authority и не разрешает external publication. Secret values не входят в публичные contracts/evidence; backend/provider-private payload не становится общим operator API.

## Security

Exact candidate обязан пройти Home Center CI на Python 3.12/3.13/3.14, reproducible artifact qualification, complete tests/module import, closed JSON/OpenAPI contracts, Public repository privacy boundary, Infrastructure neutrality и CodeQL Python `security-extended` с fail-closed medium-or-higher gate. Reviewed CodeQL exceptions допустимы только как узкие exact-source-bound reviews и становятся недействительными при source drift.

## Upgrade / rollback

Поддерживаемая release boundary: официальный Public Stable 0.58.0 → 0.59.0. Exact candidate должен пройти clean packaging/checksum verification, install/upgrade, service health/restart, сохранение пользовательского state/config/local-admin credentials, rollback/forward-recovery и exact release identity checks. Candidate identity не переписывается внутри qualification: `VERSION`, package metadata, runtime `__version__`, UI, wheel и deployment artifact обязаны соответствовать 0.59.0.

## Явно не заявлено

- multi-node HA / automatic failover — не заявлены как квалифицированные в 0.59.0;
- universal production policy backend — не заявлен без отдельного qualified adapter/backend evidence;
- commercial launch clearance — не заявлен этим техническим релизом;
- automatic infrastructure mutation и external publication не входят в release scope.

0.59.0 может быть продвинут в bounded technical Public Stable только после exact-candidate qualification обязательных security, install/upgrade/rollback, target-node и immutable artifact gates. Optional HA/provider/commercial evidence не должно быть выдумано или переноситься между candidate identities.
