# Home Center 0.24.0

Status: development qualification candidate.

Home Center 0.24 extends the cumulative home-service lifecycle with explicit
read-back verification after the authorized durable state transition added in
0.23 and with a hash-chained audit boundary for the exact authorized apply
request.

## Durable-state read-back verification

- `verify_transition_apply()` reads the current durable service-instance state after an apply receipt has been produced.
- Verification binds the exact receipt, authorization, commit, decision, instance, target state, generation and resource version.
- A matching state produces a deterministic `home-service-transition-verification.v1` evidence record with `verified=true`.
- Verification is read-only: it does not change desired or actual state and cannot authorize a subsequent mutation.

## Drift detection

- Missing instances are reported as `instance_not_found`.
- State, generation and resource-version mismatches are reported independently, so a caller can distinguish stale evidence from an unexpected lifecycle transition.
- A later legitimate transition therefore invalidates the old receipt verification instead of silently treating historical evidence as current state.
- Ambiguous apply receipts that claim both a fresh write and an idempotent replay, or neither, are rejected before verification.

## Audited apply boundary

- `apply_transition_commit_audited()` validates the exact commit/authorization binding before an audit record is written.
- The audit entry records actor, reason, correlation ID, authorization, decision, source/target state and exact generation/resource-version boundary.
- The audit chain is persisted before entering the durable compare-and-swap apply step; an unavailable audit store therefore fails closed before service state can change.
- The audit action is explicitly a requested/authorized intent. The existing apply receipt remains the result evidence for the durable transition and does not authorize a further mutation.
- Invalid or cross-boundary authorization is rejected before both audit persistence and state mutation.

## Artifact qualification

- Release identity is `0.24.0` across VERSION, package metadata and runtime metadata.
- The release artifact must contain the 0.23 durable apply boundary, the 0.24 verification runtime and the audited transition boundary.
- The verification JSON contract remains closed to unknown fields and carries explicit non-mutation guarantees.

## Cumulative guarantees

- Home Center 0.22 execution admission, worker claim, execution revalidation, result evidence and inert transition decision guarantees remain required.
- Home Center 0.23 explicit durable authorization, compare-and-swap commit and idempotent apply receipt remain required.
- External publication remains disabled unless separately and explicitly enabled by the product configuration.
- A development qualification pass does not by itself authorize an official release.

The 0.24 branch remains a development candidate until its complete acceptance and release gates pass.
