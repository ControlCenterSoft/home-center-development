# Home Center 0.34.0

Status: development qualification candidate.

Home Center 0.34 extends module candidate-set compatibility with exact-state
revalidation. The contract answers whether a previously evaluated candidate set
is still current after the runtime compatibility snapshot or the candidate set
itself changes.

## Module Candidate Set Revalidation

`revalidate_module_candidate_set()` first reconstructs the original
`home-center.module-candidate-set-decision.v1` from the original canonical
runtime snapshot and exact candidate manifests/artifact evidence. A caller
cannot reuse a modified `mcsd-*` object as trusted input.

The function then independently evaluates the candidate set against a fresh
canonical runtime snapshot. A caller may provide the same candidate inputs or a
fresh candidate composition when the planned set itself changed.

The result is
`home-center.module-candidate-set-revalidation.v1` with a deterministic
`mcsr-*` identity.

## Drift detection

The revalidation records exact drift for:

- Home Center version;
- architecture and operating system;
- runtime capability set;
- installed-module state;
- planned-module state;
- candidate membership;
- candidate version and artifact binding;
- per-candidate compatibility status/reasons;
- blocked-module set and aggregate compatibility state.

A runtime change makes the previous exact-state evidence stale even if every
candidate remains compatible. A candidate that is added, removed, upgraded or
bound to different artifact evidence also makes the previous set stale.

`stale_modules` identifies candidate modules whose exact compatibility evidence
changed or whose membership changed.

## Fail-closed evidence boundary

The original candidate-set decision is never trusted by identity alone. It must
reconstruct exactly from the original runtime snapshot and candidate inputs.
Malformed or tampered original evidence is rejected.

The fresh runtime snapshot is also revalidated through the existing canonical
snapshot and candidate-set evaluator. Invalid fresh snapshot or candidate
evidence is rejected instead of producing a permissive result.

## Authority boundary

Candidate-set revalidation is evidence only:

- `installation_authorized = false`;
- `execution_authorized = false`;
- `production_mutation_enabled = false`;
- `external_publication_authorized = false`.

The contract does not install, upgrade, remove or execute a module. It does not
change Desired State or Actual State and does not grant permission to mutate
Home Center infrastructure.

## Contract and tests

The release candidate includes the closed JSON Schema
`contracts/modules/module-candidate-set-revalidation.v1.schema.json` and
targeted tests for:

- exact-current revalidation and deterministic candidate ordering;
- Home Center version drift;
- capability drift;
- installed-module conflict drift;
- candidate membership changes;
- candidate version/artifact replacement;
- tampered original candidate-set evidence;
- tampered fresh compatibility snapshots;
- non-authorizing closed-schema invariants.

No persistent-state migration is required by this contract.
