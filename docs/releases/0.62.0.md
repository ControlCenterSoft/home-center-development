# Home Center 0.62.0

Status: source foundation prepared; not Release Candidate and not Public Stable.

## Scope prepared in this slice

0.62 continues the Roadmap role-driven identity/account provisioning line on top of the Policy Composer and parental-policy foundations already present in the current Stable lineage. Canonical Public Stable at preparation time is 0.61.2.

Prepared source boundaries:

- typed local/directory identity-provider capability evidence;
- exact Household snapshot/member/role/policy/provider binding;
- deterministic content-addressed provisioning plan;
- explicit local vs portable home-directory and profile modes;
- strict reconstruction that rejects unknown fields, evidence tampering and authority escalation;
- Cozy and Full plan projections that do not claim an account was created;
- explicit isolation of the existing local emergency administrator;
- confirmation-gated typed provider execution request using only `secret://` references;
- exact-bound read-only account-absence/name-conflict preflight with freshness and fail-closed `exists` / `conflict` / `unknown` handling;
- durable Job persisted before provider mutation and append-only Audit evidence for the execution outcome;
- deliberately registered typed runtime adapter requiring separate `start` mutation and read-only `observe` methods;
- provider start is invoked at most once for one durable idempotent attempt; timeout/malformed/ambiguous provider outcome becomes a failed non-retry-safe Job and is never automatically replayed;
- exact provider-operation-bound read-back observation and post-condition verification for account identity, home directory and profile;
- provider command acceptance remains non-success until fresh read-back proves the exact requested post-condition;
- replay of a succeeded idempotency key returns persisted verified evidence without provider reinvocation; replay of a failed attempt cannot silently retry the provider;
- secret reference values are not persisted in Job/Audit evidence; only count and content digest are retained;
- separate fail-closed member/account binding transition consumes only the persisted verified execution receipt, revalidates current parent/admin authority and the exact Household snapshot, persists one content-addressed binding with CAS/read-back, and never reinvokes the provider;
- the binding transition keeps credential material absent, the emergency local administrator isolated, privilege grants unauthorized and external publication unauthorized;
- conflicting or stale Household/binding state fails closed and cannot overwrite an existing binding; replay of the exact successful transition returns the same durable receipt without duplicate Job/Audit state;
- backup/restore qualification preserves the durable verified execution Job, binding state, transition receipt and Audit chain;
- exact-bound identity-provider qualification evidence requires a real provider and real target exercise, account-absence preflight, start/read-back contracts, durable Job-before-side-effect ordering, secret-reference-only handling, fail-closed ambiguous outcomes, no automatic mutation retry, separate post-condition verification, emergency-admin isolation, privilege/publication denial and provider-specific recovery evidence;
- a concrete provider adapter can be wrapped as qualification-bound only when its provider identity/evidence, adapter artifact and exact Home Center candidate identity match one qualified decision; the decision itself grants no provider execution, durable state mutation, release or publication authority;
- source-prepared product API separates the qualification-bound mutation/read-back adapter from a separately exact-bound **read-only** account-preflight observer; the qualification wrapper is not silently treated as granting a discovery capability that it does not expose;
- authenticated same-origin product API requests contain only user intent, `plan_id`, opaque `secret://` references, and durable Job identities: provider qualification evidence, preflight observations and verified execution receipts are never accepted from the HTTP client;
- planning authorizes the current Household parent/admin before provider lookup, so an unauthorized actor cannot use the endpoint to enumerate configured providers or target-member state;
- execute performs a new server-side exact plan/RBAC/provider revalidation and obtains a fresh read-only account-absence preflight immediately before entering the durable one-shot execution runtime; a UI preflight response is not reused as execution authority;
- the local bind step accepts only the durable execution Job ID, loads the verified receipt from StateStore and then enters the already-qualified separate binding transition; the client cannot submit a replacement receipt;
- execute and bind require bounded idempotency keys; cross-origin/external requests remain denied by the inherited runtime fences;
- wheel and node deployment artifact membership qualification covers the 0.62 planning, preflight, execution, verification, binding-transition, provider-qualification and prepared API runtimes plus their closed JSON schemas.

## Safety boundary

This source slice does **not**:

- provide a built-in production local or directory provider adapter;
- register any provider merely because the HTTP/API source exists;
- create or modify a directory object except through a separately registered exact qualification-bound adapter;
- accept provider capability/qualification evidence, preflight observations or verified execution receipts from an HTTP client;
- set, return or persist password/token/credential values;
- grant operating-system, sudo/root, directory-admin or similar privileges;
- change the emergency local administrator identity;
- automatically retry an ambiguous provider mutation;
- claim provider command acceptance as account-creation success;
- let the external provider receipt mutate Home Center member/account state directly; the local binding is a separate exact-state transition after verified read-back;
- treat provider qualification evidence as runtime execution, product release or external-publication authority;
- publish any service externally.

Reserved emergency account names `admin`, `administrator` and `root` are rejected by the planning contract. Portable home/profile requests fail closed unless exact provider evidence explicitly advertises support. Execution revalidates a still-fresh exact account-absence observation immediately before the durable Job and provider call. Credentials remain opaque `secret://` references; credential-value access stays unauthorized. Read-back observations are read-only, exact-bound and secret-free. The separate binding transition revalidates current Household state and parent/admin authority, persists no credential material, and has no provider-call path. Qualification decisions are content-addressed to the exact candidate/provider/adapter/evidence tuple and reject cross-candidate or provider drift.

## Required before executable provisioning is complete

Before 0.62 can claim a production identity provisioning capability, a concrete local and/or directory adapter must be implemented and must produce evidence accepted by the exact-bound qualification gate, including real target/provider exercise and provider-specific recovery semantics. Its account-preflight observer must also be bound read-only to the exact provider evidence, adapter artifact and qualification decision.

The prepared API source still requires normal runner qualification and later production composition/routing after the independent runtime-composition work is integrated. Then 0.62 still requires exact release identity, supported install/upgrade/rollback qualification from Public Stable 0.61.2, final security/release artifact gates and guarded Public Stable promotion. Portable home/profile support may be claimed only for providers that pass their own qualification. Multi-node HA and commercial-launch claims remain separate qualification/activation boundaries.

Current Public Stable is 0.61.2. This preparation does not change `VERSION`, create a release candidate, claim provider/HA support or grant commercial-launch clearance.
