# Home Center 0.62.0

Status: source foundation prepared; not Release Candidate and not Public Stable.

## Scope prepared in this slice

0.62 continues the Roadmap role-driven identity/account provisioning line on top of the Policy Composer and parental-policy foundations already present in the current Stable lineage. Canonical Public Stable at preparation time is 0.61.0.

Prepared source boundaries:

- typed local/directory identity-provider capability evidence;
- exact Household snapshot/member/role/policy/provider binding;
- deterministic content-addressed provisioning plan;
- explicit local vs portable home-directory and profile modes;
- strict reconstruction that rejects unknown fields, evidence tampering and authority escalation;
- Cozy and Full plan projections that do not claim an account was created;
- explicit isolation of the existing local emergency administrator;
- confirmation-gated typed provider execution request using only `secret://` references;
- strict provider-acceptance result contract that keeps account/home/profile/post-condition verification false until separate read-back evidence exists;
- exact-bound read-only account-absence/name-conflict preflight with freshness and fail-closed `exists` / `conflict` / `unknown` handling;
- exact provider-operation-bound read-back observation and post-condition verification for account identity, home directory and profile;
- stale/future/incomplete/ambiguous read-back evidence cannot become verified success;
- wheel and node deployment artifact membership qualification for the 0.62 planning, preflight, execution-contract and verification runtimes plus closed JSON schemas.

## Safety boundary

This source slice does **not**:

- create a local or directory account by itself;
- create or modify a directory object by itself;
- set, return or authorize password/token/credential values;
- create a home directory or portable profile by itself;
- grant operating-system, sudo/root, directory-admin or similar privileges;
- change the emergency local administrator identity;
- register or invoke a concrete production identity provider adapter;
- claim provider command acceptance as account-creation success;
- authorize durable Household/member state mutation merely because provider read-back verified the external post-condition;
- publish any service externally.

Reserved emergency account names `admin`, `administrator` and `root` are rejected by the planning contract. Portable home/profile requests fail closed unless the exact provider evidence explicitly advertises support. The execution-request boundary revalidates the exact provider identity/evidence and requires explicit confirmation; credentials remain opaque `secret://` references and credential-value access stays unauthorized. Preflight and verification observations are read-only, exact-bound and secret-free.

## Required before executable provisioning is complete

The remaining execution runtime must deliberately register a qualified local/directory provider adapter, persist durable Job/Audit evidence before provider mutation, handle ambiguous outcomes without unsafe automatic retry, and bind any later Home Center durable-state transition to the exact verified evidence through its own fail-closed transition/read-back boundary. Concrete local/directory provider support and any portable-profile provider require their own exact-bound qualification.

Current Public Stable remains 0.61.0. This preparation does not change `VERSION`, create a release candidate, claim provider/HA support or grant commercial-launch clearance.
