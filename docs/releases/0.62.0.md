# Home Center 0.62.0

Status: source development in progress; not Release Candidate and not Public Stable.

## Scope prepared so far

0.62 continues the Roadmap role-driven identity/account provisioning line on top of the Policy Composer and parental-policy foundations already present in the current Stable lineage. Canonical Public Stable at preparation time is 0.61.0.

Prepared source boundaries:

- typed local/directory identity-provider capability evidence;
- exact Household snapshot/member/role/policy/provider binding;
- deterministic content-addressed provisioning plan;
- explicit local vs portable home-directory and profile modes;
- strict reconstruction that rejects unknown fields, evidence tampering and authority escalation;
- Cozy and Full plan projections that do not claim an account was created;
- explicit isolation of the existing local emergency administrator;
- explicit confirmation boundary for the exact current plan;
- content-addressed read-only account-absence/name-conflict preflight evidence;
- bounded preflight freshness with future/stale evidence rejection;
- deterministic `confirmed-awaiting-execution` receipt that still grants no provider or infrastructure mutation authority.

## Confirmation and account preflight

Confirmation does not trust stale or caller-constructed plan evidence. The complete plan is strictly reconstructed and then rebuilt against the current Household snapshot, member role, Effective/Composed Policy and exact provider capability evidence. Any drift fails closed.

The account preflight is deliberately read-only and accepts only a fresh exact-bound `absent` result. `exists` is an explicit conflict, while `unknown` is never treated as absence. The current maximum freshness budget is five minutes and callers may require a stricter positive bound.

Neither a positive preflight nor explicit confirmation creates an account. A successful receipt means only that the exact plan has been confirmed and is waiting for a separate typed execution boundary.

## Safety boundary

The current source line does **not**:

- create a local or directory account;
- create or modify a directory object;
- set, return or authorize password/token/credential values;
- create a home directory or portable profile;
- grant operating-system, sudo/root, directory-admin or similar privileges;
- change the emergency local administrator identity;
- execute a provider or mutate infrastructure;
- publish any service externally.

Reserved emergency account names `admin`, `administrator` and `root` are rejected by the planning contract. Portable home/profile requests fail closed unless the exact provider evidence explicitly advertises support. Confirmation and preflight evidence hard-code provider execution, credential material, emergency-admin mutation, arbitrary privilege grant, infrastructure mutation and external publication authority to false.

## Remaining work before actual provisioning

A later execution boundary remains separate and must add, qualify and preserve at least:

- typed provider execution request/result contracts;
- secret-reference-only credential/bootstrap material handling where supported;
- durable Job/Audit/idempotency around execution;
- exact account-absence/conflict revalidation immediately before mutation;
- ambiguous provider-outcome handling without unsafe automatic retry;
- account/home/profile read-back and post-condition verification before success;
- recovery/cleanup semantics for partial outcomes;
- concrete supported local/directory adapter qualification;
- final install/upgrade, packaging, security and release qualification for the exact 0.62 identity.

Current Public Stable remains 0.61.0. This preparation does not change `VERSION`, create a release candidate, claim provider/HA support or grant commercial-launch clearance.
