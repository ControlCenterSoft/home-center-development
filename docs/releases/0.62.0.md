# Home Center 0.62.0

Status: source foundation prepared; not Release Candidate and not Public Stable.

## Scope prepared in this slice

0.62 continues the Roadmap role-driven identity/account provisioning line on top of the Policy Composer and parental-policy foundations already present in the current Stable lineage. Canonical Public Stable at preparation time is 0.61.2.

Prepared source boundaries:

- typed local/directory identity-provider capability evidence and exact Household snapshot/member/role/policy/provider binding;
- deterministic content-addressed provisioning plan with explicit local vs portable home/profile modes and emergency-admin isolation;
- confirmation-gated provider execution using only `secret://` references, exact account-absence preflight, durable Job-before-side-effect ordering, one-shot mutation, read-only post-condition verification and fail-closed ambiguous outcomes;
- replay/restart returns persisted verified evidence without provider reinvocation and backup/restore preserves verified execution evidence;
- separate fail-closed member/account binding transition consumes only persisted verified execution evidence, revalidates parent/admin authority and exact Household state, persists a content-addressed binding with CAS/read-back and never calls the provider;
- exact-bound provider qualification requires real provider + real target exercise, provider/adapter/candidate binding, start/read-back contracts, no-secret evidence, emergency-admin isolation, privilege/publication denial and provider-specific recovery semantics;
- qualification-bound adapters reject candidate/provider/artifact drift and qualification itself grants no provider execution, durable state mutation, release or publication authority;
- server-authoritative identity provisioning API wiring exposes separate authenticated same-origin plan, read-only preflight and explicitly confirmed execute boundaries; clients select only an already-registered qualified provider ID and cannot submit provider capability or qualification evidence;
- provider registration re-binds the exact qualification decision, provider capability, adapter artifact and candidate identity before the adapter can reach the durable execution runtime; account preflight is re-read server-side immediately before execution;
- wheel and node deployment artifact qualification covers planning, preflight, execution, verification, binding transition, provider qualification and API runtimes plus their closed JSON request schemas.

## Safety boundary

This source slice does **not**:

- provide a built-in production local or directory provider adapter;
- accept provider capability, qualification evidence or account-preflight observations from an HTTP client;
- set, return or persist password/token/credential values;
- grant operating-system, sudo/root, directory-admin or similar privileges;
- change the emergency local administrator identity;
- automatically retry an ambiguous provider mutation;
- claim provider command acceptance as account-creation success;
- let an external provider receipt mutate Home Center member/account state directly; local binding remains a separate exact-state transition after verified read-back;
- treat provider qualification evidence as runtime execution, product release or external-publication authority;
- publish any service externally.

Reserved emergency account names `admin`, `administrator` and `root` are rejected by planning. Portable home/profile requests fail closed unless exact provider capability evidence advertises support. Credentials stay opaque `secret://` references and raw references are excluded from Job/Audit evidence. The API revalidates Household parent/admin authority, exact plan identity, qualified provider binding and a fresh server-side account-absence observation before provider execution.

## Required before executable provisioning is complete

Before 0.62 can claim production identity provisioning, a concrete local and/or directory adapter must be implemented and must produce evidence accepted by the exact-bound qualification gate on a real target/provider. The already-qualified separate member/account binding transition still needs a bounded product/API orchestration path after verified execution. Exact 0.62 release identity, supported install/upgrade/rollback qualification from Public Stable 0.61.2, final security/release-artifact gates and guarded Public Stable promotion remain required. Portable home/profile support may be claimed only for providers that pass their own qualification.

Current Public Stable is 0.61.2. This preparation does not change `VERSION`, create a release candidate, claim provider/HA support or grant commercial-launch clearance.
