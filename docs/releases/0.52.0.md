# Home Center 0.52.0

Статус: исходный пакет подготовлен для последующей квалификации.

## Назначение

Home Center 0.52.0 продолжает mobile-first сценарий «Уютный → Семья» и добавляет безопасную проверку необходимости управления для уже зарегистрированного устройства.

Для конкретного устройства Home Center различает три состояния:

- `satisfied` — управление уже подтверждено в состоянии Household;
- `required` — политика роли требует управляемое устройство, но управление ещё не подтверждено;
- `optional` — обязательное управление для роли не требуется.

Для состояния `required` система может только предложить следующий будущий шаг `household.device.management.enroll`. План привязан к точным `snapshot_id`, `resource_version`, `generation`, устройству и владельцу. Он не выбирает MDM/provider, учётные данные или конкретный механизм enrollment.

## Интерфейс «Уютный»

В разделе «Семья» зарегистрированные устройства получают отдельное действие «Проверить необходимость». Само открытие раздела не создаёт план и не изменяет состояние устройства.

Пользователь видит только подтверждённое состояние:

- управление уже подтверждено;
- управление требуется, но ещё не применено;
- управление необязательно.

Для устройства ребёнка, которому требуется управление, интерфейс прямо сообщает, что способ управления будет выбираться и подтверждаться отдельно и что текущая проверка ничего не устанавливает и не применяет.

## Граница безопасности

Версия 0.52.0 остаётся строго planning-only для управления устройствами. Каждый план фиксирует:

- `provider_selected=false`;
- `provider_execution_authorized=false`;
- `policy_application_authorized=false`;
- `infrastructure_mutation_authorized=false`;
- `external_publication_authorized=false`.

План не изменяет `managed`, не выполняет enrollment Android/iOS/Windows, не меняет DNS, VPN, Wi-Fi, firewall или filtering policy, не запускает provider и не изменяет внешний Desired State.

Инвариант 0.51 сохраняется: регистрация устройства сама по себе не является доказательством, что устройство управляется.

## API

Добавляется аутентифицированный same-origin endpoint:

`POST /api/v1/household/devices/management/plan`

Схема запроса: `home-center.household-device-management-plan-request.v1`.

Схема результата: `home-center.household-device-management-plan.v1`.

Действующий член Household определяется по привязке аутентифицированного actor. Клиент не может подставить произвольного административного участника.

## Совместимость и данные

Постоянная схема данных не меняется, миграция не требуется. Планирование читает текущее Household-состояние и записывает только audit-событие. Текущие single-node и HA deployment-модели не получают новых инфраструктурных мутаций.

## Требования перед выпуском

Перед переводом 0.52.0 в официальный релиз должны быть квалифицированы накопительные границы 0.49–0.51, новый management-planning слой, API/UI-контракт, отсутствие изменения Household-состояния и отсутствие provider/policy/infrastructure authority. GitHub runner в рамках non-runner разработки не запускался; qualification выполняется отдельным release-потоком.
