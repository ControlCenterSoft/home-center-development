# Home Center 0.52.0

Статус: release candidate до завершения обязательной qualification и официальной публикации.

## Объём релиза

Home Center 0.52.0 продолжает «Уютный → Семья» и добавляет безопасную read-only оценку необходимости управления для уже зарегистрированных устройств.

Для каждого устройства Home Center возвращает одно из трёх состояний:

- `required` — действующая роль пользователя требует управляемого устройства, но подтверждённого managed-состояния ещё нет;
- `satisfied` — управление требуется и в продуктовой модели уже подтверждено `managed=true`;
- `optional` — действующая роль не требует управления устройством.

Оценка является **plan-only**. Она не выбирает MDM/provider, не выполняет enrollment, не применяет DNS/VPN/Wi‑Fi/сертификаты или другие политики и не изменяет инфраструктуру.

## API и безопасность

Добавлен аутентифицированный read-only endpoint:

`GET /api/v1/household/devices/management`

Ответ привязан к текущим Household `snapshot_id`, `resource_version` и `generation`. Он содержит только проверенное продуктовое состояние и явно фиксирует:

- `plan_only=true`;
- `provider_selected=false`;
- `policy_application_authorized=false`;
- `provider_execution_authorized=false`;
- `infrastructure_mutation_authorized=false`;
- `external_publication_authorized=false`.

Состояние `required` не означает, что политика уже применена. Состояние `satisfied` возможно только при одновременно действующем требовании роли и подтверждённом `managed=true` в Household product state.

## Fail-closed поведение

Некорректное или неполное Household runtime-state не преобразуется в положительный результат: endpoint возвращает ошибку доступности статуса. Для ненастроенного Household возвращается пустой plan-only отчёт без провайдерной или инфраструктурной authority.

## Совместимость и обновление

Изменение не меняет формат сохранённого Household state и не требует миграции данных. Все возможности 0.51.0, включая confirmation-gated регистрацию устройств, сохраняются. Установка и обновление должны выполняться только штатным Stable/release-candidate путём с сохранением пользовательских данных, настроек и паролей и с обычными health/rollback проверками.

## Коммерческая граница

0.52.0 не добавляет новый Market-модуль, платный entitlement или внешний коммерческий provider. Существующая модель лицензирования не расширяется. Любой будущий MDM/provider должен проходить отдельную юридическую, лицензионную и security qualification до включения реального enrollment или применения политики.

## Qualification boundary

Release artifact обязан содержать `household_device_management.py` и `api_v3.py`. Qualification должна пройти на Python 3.12 и 3.13 с полным pytest-набором, воспроизводимой сборкой wheel, privacy-boundary и infrastructure-neutrality проверками на точном SHA release candidate.
