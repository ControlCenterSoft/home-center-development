# Home Center 0.52.0

Status: source package ready for qualification.

## Scope

Home Center 0.52.0 continues the mobile-first «Уютный → Семья» flow with a provider-neutral management plan for devices that are already registered in Household state.

The release distinguishes three states for one exact registered device:

- `satisfied` — management is already represented as confirmed in Household state;
- `required` — the member RolePreset requires a managed device, but the device is not yet managed;
- `optional` — the member RolePreset does not require management and the device may remain registered without an enrollment action.

For `required`, Home Center may recommend a future `household.device.management.enroll` action. The recommendation is bound to the exact Household `snapshot_id`, `resource_version` and `generation` and identifies the device and its owner. It does not select an MDM/provider, credentials or implementation-specific enrollment mechanism.

## Cozy interface

The «Семья» view lists registered devices separately from member creation and registration controls. A user explicitly selects «Проверить необходимость» for a device before Home Center requests a management plan. Opening the page by itself does not create management plans.

The UI communicates only verified Household state:

- management already confirmed;
- management required but not yet applied;
- management optional.

For a required unmanaged child device, the UI explicitly says that a future management method must be selected and separately confirmed and that nothing has been installed or applied yet.

## Safety boundary

This release is planning-only for device management. Every management plan fixes:

- `provider_selected=false`;
- `provider_execution_authorized=false`;
- `policy_application_authorized=false`;
- `infrastructure_mutation_authorized=false`;
- `external_publication_authorized=false`.

The plan does not change the Household device `managed` flag, does not enroll Android/iOS/Windows devices, does not modify DNS, VPN, Wi-Fi, firewall or filtering policy, does not execute a provider and does not mutate external Desired State.

The existing 0.51 registration invariant remains unchanged: registering a device is not proof that the device is managed.

## API

Adds authenticated, same-origin:

`POST /api/v1/household/devices/management/plan`

Request schema: `home-center.household-device-management-plan-request.v1`.

Result schema: `home-center.household-device-management-plan.v1`.

The acting Household member is resolved from the authenticated actor binding; callers cannot nominate an arbitrary administrative member.

## Qualification boundary

Release qualification must preserve the cumulative 0.49 confirmed member flow, the 0.51 confirmed device-registration flow and the new 0.52 management-planning boundary. The release wheel must contain both `household_device_management.py` and `household_device_management_runtime.py`.

No persistent-state migration is required.
