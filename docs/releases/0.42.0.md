# Home Center 0.42.0

Status: source package ready for qualification.

## Scope

Home Center 0.42.0 adds a canonical, versioned requirement-set contract for the
Home Service/API contract revisions required by a module.

`home-center.module-home-service-contract-requirement-set.v1` gives the
requirement set its own deterministic `mhscr-*` identity. The identity binds the
Home Center version, module identity/version, target Home Service identity and
canonical ordered set of required revisioned contracts.

This separates exact requirement identity from the broader module manifest and
from the Home Service compatibility binding. A later binding can therefore
prove exactly which requirement set was evaluated and can make requirement-only
drift stale without treating an unchanged manifest artifact as sufficient
evidence.

Malformed, duplicate, empty, noncanonical or tampered serialized requirements
are rejected fail-closed. Requirement input is consumed through a bounded
64-item contract set with one overflow sentinel, so oversized or unbounded
iterables cannot be fully materialized. The serialized validation boundary
accepts only the exact in-memory requirement value or a plain JSON-style
`dict`/`list` shape; polymorphic mapping/container and string subclasses are
rejected instead of being treated as trusted evidence.

## Safety boundary

Requirement-set evidence is descriptive only. It does not authorize admission,
installation, execution, production mutation or external publication.

The contract is topology-neutral and infrastructure-neutral. It adds no
Jobs/Operations behavior, Cluster/HA orchestration, placement semantics or
release-promotion logic. Existing authentication policy is unchanged.

No persistent-state migration is required.

## Verification boundary

The source package includes the runtime contract, closed JSON Schema,
deterministic identity and targeted unit/contract tests, including bounded-input
and serialized-boundary regressions. Official publication requires the
repository's complete qualification, security/privacy and release governance
checks for the exact candidate revision.
