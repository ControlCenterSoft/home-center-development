# Home Center 0.53.0

Status: source package ready for qualification.

## Scope

Home Center 0.53.0 adds the next bounded «Уютный → Семья» step after provider-neutral management planning: an explicit enrollment proposal and a separate confirmation of the user's intent to continue to provider resolution.

The boundary applies only when the exact current device-management plan is `required`: the device is registered, its owner RolePreset requires management, and `managed=false` is still the verified Household state.

The enrollment proposal is bound to the exact Household `snapshot_id`, `resource_version`, `generation`, authenticated parent member, device, owner and underlying management-plan identity. If Household state changes before confirmation, the proposal is rejected as stale and must be planned again.

## Confirmation semantics

`confirm` records one thing only: explicit consent to proceed to the later provider-resolution stage.

A successful confirmation returns outcome `confirmed-for-provider-resolution`. A safe retry against the same exact Household state returns `already-confirmed`.

Confirmation does not enroll the device and does not modify Household state. In particular, the registered device remains `managed=false` after confirmation.

## Safety boundary

Both proposal and confirmation evidence fix:

- `provider_resolution_required=true`;
- `provider_selected=false`;
- `provider_execution_authorized=false`;
- `policy_application_authorized=false`;
- `managed_state_change_authorized=false`;
- `infrastructure_mutation_authorized=false`;
- `external_publication_authorized=false`.

No provider credentials, provider identifier, enrollment token, MDM profile, DNS/VPN/Wi-Fi/firewall/filtering mutation, external Desired State mutation or external publication is introduced.

Devices whose management state is `optional` or `satisfied` cannot create an enrollment proposal through this boundary.

## API

Adds authenticated, same-origin endpoints:

- `POST /api/v1/household/devices/enrollment/plan`
- `POST /api/v1/household/devices/enrollment/confirm`

Planning request schema: `home-center.household-device-enrollment-plan-request.v1`.

Confirmation request schema: `home-center.household-device-enrollment-confirm-request.v1`; `confirmed` must be exactly `true`.

The acting Household member is always resolved from the authenticated actor binding. A caller cannot nominate an arbitrary parent identity.

## Cozy interface

The enrollment card appears only after the user explicitly checks management necessity and receives `required`. The user then separately chooses «Подготовить подключение» and receives an enrollment proposal. A second explicit action «Подтвердить переход к настройке» records consent.

The interface states that the provider is still not selected, nothing is installed, and device management is still not enabled. After confirmation it says that only consent has been saved and the next stage is selection of an appropriate management method.

## Qualification boundary

0.53 qualification is cumulative over the confirmed family-member flow, confirmed device-registration flow and provider-neutral management planning from 0.49–0.52. The wheel must also contain `household_device_enrollment.py` and `household_device_enrollment_runtime.py`.

No persistent Household-state migration is required.
