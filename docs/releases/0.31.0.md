# Home Center 0.31.0

Status: development qualification candidate.

Home Center 0.31 adds a canonical runtime compatibility snapshot identity and a
batch binding for module-admission decisions. The package makes it possible to
prove that several admission decisions were evaluated against one exact Home
Center runtime compatibility state instead of accidentally mixing decisions
from different product versions or module environments.

## Canonical compatibility snapshot

`home_center.module_compatibility_snapshot.build_module_compatibility_snapshot()`
normalizes and binds:

- Home Center semantic version;
- runtime architecture and operating-system identifiers;
- the complete bounded capability set;
- installed module IDs and exact semantic versions.

Capability and installed-module ordering is canonicalized before a deterministic
`mcs-*` snapshot identity is calculated. Duplicate or malformed input fails
closed.

The snapshot is evidence only. It does not discover the runtime, install a
module, execute provider code, mutate infrastructure or enable publication.

## Admission decision binding

`bind_module_admission_decisions_to_snapshot()` accepts one canonical snapshot
and one or more exact `home-center.module-admission-decision.v1` records.

Before binding, the snapshot identity is reconstructed from its recorded fields.
Each admission record must retain a self-consistent deterministic `madm-*`
identity, the expected schema and non-authorizing flags. Its recorded Home Center
version, architecture, operating system, capability set and installed-module
state must exactly equal the canonical snapshot.

A decision from another runtime state is rejected with
`admission_decision_snapshot_mismatch`. Duplicate decisions for the same module
are rejected so one binding cannot silently contain two competing compatibility
answers for one module identity.

Accepted decision references are sorted deterministically and produce one
`masb-*` binding identity. Reordering otherwise identical decisions therefore
does not change the resulting evidence.

## Safety boundary

Both new contracts fix:

- `installation_authorized = false`;
- `execution_authorized = false`;
- `production_mutation_enabled = false`;
- `external_publication_authorized = false`.

A compatible admission decision bound to a snapshot remains compatibility
evidence only. It does not authorize installation, lifecycle actions, Jobs,
provider execution, service mutation, network changes or publication.

## Contracts and tests

The candidate adds closed JSON Schemas for:

- `home-center.module-compatibility-snapshot.v1`;
- `home-center.module-admission-snapshot-binding.v1`.

Targeted tests cover deterministic snapshot identity, capability ordering,
multi-decision binding, deterministic decision ordering, mixed Home Center
version/capability/module-state rejection, duplicate module decisions, tampered
decision identity, authority-flag tampering, tampered snapshot identity and
deterministic `mcs-*`/`masb-*` identifiers.

Release identity is `0.31.0` across VERSION, Python package metadata and runtime
package metadata. No data migration is required because this package adds
side-effect-free compatibility evidence contracts on top of the 0.29/0.30
module-admission line.

The 0.31 branch remains a development candidate until its complete qualification
and release gates pass.
