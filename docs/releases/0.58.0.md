# Home Center 0.58.0

**Статус:** разработка; ограниченный слой 0.58, не Release Candidate и не Public Stable.

## Цель релиза

0.58.0 продолжает границу 0.57.0 после принятия команды подключения провайдером. Новый слой отдельно доказывает фактическое завершение подключения и только после точной проверки разрешает Home Center изменить локальное состояние устройства с `managed=false` на `managed=true`.

## Реализовано

- введён отдельный verification plan, привязанный к точным execution plan/job, операции провайдера, устройству, члену семьи и исходному Household snapshot;
- provider verification adapter допускается только при явном `verification_read_only=true` и получает только read/verify request без полномочий изменять Household state;
- ответ провайдера принимается только при точном совпадении verification id, provider operation и device id;
- провайдер обязан доказать `enrollment_completed=true` и `post_condition_verified=true`, но обязан оставить `managed_state_change_authorized=false`;
- Home Center формирует разрешение на managed-state transition только после собственной fail-closed проверки всех связей;
- устаревший Household snapshot, отменённое execution, уже управляемое устройство, подмена provider operation и попытка провайдера присвоить mutation authority блокируются;
- успешный переход создаёт новый Household snapshot/commit и меняет только поле целевого устройства `managed` на `true`;
- durable verification runtime использует явное подтверждение, idempotency key, Job state, Audit evidence и промежуточное `applying` состояние;
- подтверждённое provider evidence сохраняется до локального managed-state commit; повтор после commit принимается только если установленное Household-состояние совпадает с ожидаемым snapshot;
- добавлены защищённые HTTP endpoints `/api/v1/household/devices/enrollment/verification/plan` и `/confirm`, наследующие действующие authentication/origin/external-access ограничения;
- применение MDM/сетевых/файловых политик, инфраструктурные изменения и external publication остаются запрещены;
- добавлены unit/integration security tests и JSON Schema contracts для plan/request/result/receipt; итоговая qualification этого слоя пока не заявлена.

## Что намеренно не входит в этот слой

- регистрация реального production provider verification adapter по умолчанию;
- qualification конкретного provider adapter против реального сервиса;
- автоматическое применение политик после `managed=true`;
- ослабление границы полномочий 0.57/0.58;
- функциональность последующих релизов.

До qualification конкретного provider adapter и полного подтверждения release gates этот код остаётся development-состоянием и не является заявлением о готовности managed enrollment к эксплуатации.
