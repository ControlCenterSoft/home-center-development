# Home Center 0.58.0

**Статус:** разработка; bounded 0.58 slice, не Release Candidate и не Public Stable.

## Цель релиза

0.58.0 продолжает границу 0.57.0 после принятия команды подключения провайдером. Новый слой отдельно доказывает фактический post-condition подключения и только после точной проверки разрешает Home Center изменить локальное Household-состояние устройства с `managed=false` на `managed=true`.

## Реализовано в текущем slice

- введён отдельный deterministic verification plan, привязанный к exact execution plan/job, provider operation, устройству, члену семьи и исходному Household snapshot;
- provider verification adapter допускается только при явном `verification_read_only=true` и получает только read/verify request без полномочий изменять Household state;
- provider result принимается только при точном совпадении verification id, provider operation и device id;
- provider result обязан доказать `enrollment_completed=true` и `post_condition_verified=true`, но обязан оставить `managed_state_change_authorized=false`;
- Home Center выводит разрешение на managed-state transition только после собственной fail-closed проверки всех связей;
- stale Household snapshot, отменённое 0.57 execution, уже managed устройство, подмена provider operation и попытка провайдера присвоить себе mutation authority блокируются;
- успешный переход создаёт новый Household snapshot/commit и меняет только поле целевого устройства `managed` на `true`;
- durable verification runtime использует explicit confirmation, idempotency key, Job state, Audit evidence и промежуточное `applying` состояние;
- validated provider evidence сохраняется до локального managed-state commit; повтор после commit не вызывает provider повторно и принимается только если установленное Household-состояние совпадает с ожидаемым snapshot;
- добавлены guarded HTTP endpoints `/api/v1/household/devices/enrollment/verification/plan` и `/confirm`, наследующие V3 authentication/origin/external-access fences;
- применение MDM/сетевых/файловых политик, инфраструктурные изменения и external publication остаются запрещены;
- добавлены unit/integration security tests и JSON Schema contracts для plan/request/result/receipt; в этом non-runner потоке они намеренно **не запускались**.

## Что намеренно не входит в этот slice

- регистрация реального production provider verification adapter по умолчанию;
- qualification конкретного provider adapter против реального сервиса;
- автоматическое применение политик после `managed=true`;
- ослабление 0.57/0.58 границы полномочий;
- любая функциональность 0.60 и далее.

До qualification конкретного provider adapter и отдельного runner/release прохода этот код остаётся development slice и не является заявлением о готовности managed enrollment к эксплуатации.
