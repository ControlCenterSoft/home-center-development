# Home Center 0.58.0 — development notes

Status: **development only**. This document does not declare RC or Stable readiness.

Home Center 0.58 extends the qualified 0.57 enrollment-execution boundary with fail-closed
post-condition verification, explicit safe de-enrollment and bounded failed-enrollment cleanup.

Implemented and integrated on the current shared 0.58 development branch:

- closed Draft 2020-12 schemas for enrollment verification request/read-back/evidence/receipt;
- exact enrollment verification binding to plan/provider operation/device/member/execution generation;
- bounded freshness checks and content-addressed verification evidence;
- authenticated verification plan/confirm API wiring with Household parent/RBAC revalidation;
- scoped single-use re-authentication before verification execution;
- durable idempotent Jobs and Audit evidence;
- read-only verifier capability gate with fail-closed missing-verifier behavior before Job creation;
- verified evidence persisted before exact Household managed-state transition;
- Household read-back after local apply with restoration of the validated base state on mismatch;
- restart recovery for durable `verified-pending-apply` without repeating provider read-back;
- deterministic de-enrollment and failed-enrollment cleanup contracts;
- no automatic provider retry after unknown/ambiguous outcomes;
- secret values, policy mutation, device-record removal, infrastructure mutation and external
  publication remain outside these boundaries.

Qualified release evidence already present for the current 0.58 integration head includes:

- Python 3.12 / 3.13 / 3.14 exact-head development qualification;
- reproducible artifact qualification;
- deployment archive checksum/MANIFEST/runtime/contract membership;
- durable 0.58 evidence persistence through the existing StateStore backup path;
- hosted 0.57 -> 0.58 install/upgrade/rollback with config and SQLite user-state preservation;
- real-systemd 0.57 -> 0.58 install/health/rollback with service/timer/state/config preservation;
- public privacy boundary and infrastructure neutrality.

Prepared in the isolated non-runner NR1 verifier-qualification slice:

- closed `home-center.device-management-enrollment-verifier-profile.v1`;
- deterministic `home-center.device-management-enrollment-verifier-contract-qualification-receipt.v1`;
- strict verifier registry wrapper requiring matching static contract evidence before registration;
- exact provider/verifier identity, verifier revision, result schema, signal vocabulary and source
  SHA-256 binding;
- explicit `qualification_level=contract-only`, `provider_read_performed=false` and
  `production_qualified=false`;
- negative tests for writable adapters, descriptor mismatch, provider mismatch, invalid schema/signals,
  unexpected authority fields and missing qualification evidence;
- contract qualification never calls the provider and grants no provider/managed-state/policy/
  infrastructure/external-publication authority.

The isolated verifier-qualification slice is intentionally kept without a pull request because the
repository's PR workflows use GitHub-hosted runners. Ordinary pushes to the `nr1/**` branch do not
match the `main`/`release/**` push filters; zero workflow runs were observed after the source writes.
It is prepared code and is not yet shared-branch runner-qualified.

Still open before 0.58 can become a Release Candidate:

- concrete production provider verifier/adapter and live provider qualification;
- production de-enrollment/cleanup runtime Job/API wiring beyond the existing contracts;
- integration and normal exact-head qualification of the verifier contract-qualification slice;
- real target-node acceptance and multi-node HA/restart acceptance;
- final commercial/legal clearance;
- RC/Public Stable promotion.

Public Stable remains 0.56.0 until the authoritative release gates are closed. The 0.57 release
candidate path remains separate and is not re-qualified by this 0.58 development work.
