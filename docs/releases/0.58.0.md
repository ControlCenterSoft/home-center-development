# Home Center 0.58.0

Status: release candidate.

Release profile: `single-node-core`.

Home Center 0.58 extends the qualified 0.57 enrollment-execution boundary with fail-closed post-condition verification, explicit de-enrollment and bounded failed-enrollment cleanup.

## Included

- exact-bound enrollment post-condition verification with mandatory fresh provider read-back before local `managed=true`;
- Household parent/RBAC and scoped re-auth revalidation;
- durable idempotent Job/Audit/evidence persistence and restart-safe completion without provider reinvocation;
- explicit de-enrollment plan/confirm, one-shot provider mutation and mandatory exact-bound read-back before local managed-state clearing;
- ambiguous de-enrollment outcomes become `reconcile-required`; reconciliation never repeats provider mutation;
- bounded failed-enrollment cleanup that removes only the persisted single-use transient artifact reference while preserving Household/device/policy/provider state and durable Audit/evidence;
- authenticated same-origin device-management HTTP boundaries with closed OpenAPI and JSON contracts;
- backup/artifact membership for new durable evidence and runtime/contracts.

## Release qualification boundary

The exact 0.58 candidate must pass the normal Home Center CI matrix on Python 3.12/3.13/3.14, exact source identity, reproducible packaging, Public repository privacy boundary, Infrastructure neutrality and CodeQL security-extended fail-closed gating.

Install/upgrade qualification is bound to the official Home Center 0.57.0 Public Stable source identity. The release candidate must preserve user state, configuration, administrator password/session state and durable evidence through supported 0.57 -> 0.58 upgrade, restart and rollback/forward-recovery paths.

## Explicitly unclaimed capabilities

The bounded technical Stable profile does not claim:

- multi-node HA / automatic failover;
- concrete production provider execution without a separately qualified adapter;
- commercial launch clearance.

Unsupported capabilities remain fail-closed, disabled or unclaimed and are not represented as qualified PASS evidence.

Provider command acceptance is never treated as enrollment success. Until post-condition verification succeeds, `enrollment_completed=false`, `post_condition_verified=false` and `managed_state_change_authorized=false`.

This candidate does not itself grant release or external-publication authority. Official source publication and PUBLIC STABLE promotion remain separate exact-bound release steps after candidate qualification.
