# Home Center 0.58.0

Status: official release.

## Профиль релиза

Home Center 0.58.0 — bounded technical release поверх официального Public Stable 0.57.0. Релиз закрывает безопасную post-condition boundary для управления устройствами и доводит enrollment/de-enrollment lifecycle до состояния, где принятие команды provider не может быть ошибочно показано как подтверждённый результат.

Заявленный технический профиль релиза — `single-node-core`. Multi-node HA / automatic failover, concrete production provider execution и commercial launch clearance не заявляются как квалифицированные возможности 0.58.0 без отдельного exact-bound evidence. Отсутствие такого evidence не превращается в фиктивный PASS: соответствующие capabilities остаются fail-closed, disabled или unclaimed.

## Что добавлено

- authenticated enrollment post-condition verification plan/confirm boundary с same-origin, session, Household parent/RBAC и scoped re-auth fences;
- exact binding verification к enrollment plan, provider operation, device, FamilyMember, Household snapshot/resource-version/generation и candidate evidence;
- provider verifier boundary только для явно read-only adapters; отсутствие подходящего adapter блокирует verification до создания ложного успешного результата;
- fresh exact-bound provider read-back обязателен до локального перехода `ManagedDevice.managed=true`;
- verified evidence сохраняется до state transition, затем Home Center повторно читает Household state; mismatch/read-back failure восстанавливает проверенную базовую запись и не выдаёт Success;
- restart-safe completion уже сохранённого `verified-pending-apply` evidence без повторного provider invocation;
- deterministic de-enrollment plan/confirm с отдельным explicit confirmation и scoped step-up;
- provider de-enrollment mutation допускается только через зарегистрированный mutation-capable adapter и выполняется одноразово; provider acceptance не является success;
- локальный `managed=false` разрешается только после свежего exact-bound read-back `unmanaged`/`absent`;
- ambiguous/unknown de-enrollment outcome переводится в `reconcile-required`; reconciliation остаётся read-only и не повторяет provider mutation;
- bounded failed-enrollment cleanup verification/execution удаляет только persisted single-use transient artifact reference после свежего exact-bound read-back и сохраняет Household/device/policy/provider state, планы, Jobs, Audit и evidence;
- closed OpenAPI 3.1 device-management safety contract документирует фактические 0.57–0.58 HTTP boundaries без создания новых полномочий;
- backup/artifact membership включает новые runtime-модули, contracts и durable evidence.

## False-success boundary

Provider command acceptance никогда не означает успешное enrollment/de-enrollment. Для enrollment состояние `managed=true` допустимо только после отдельной post-condition verification и подтверждённого read-back. Для de-enrollment `managed=false` допустимо только после подтверждённого provider state `unmanaged` или `absent`.

Unknown, ambiguous, stale, future-dated, mismatched или incomplete evidence работает fail-closed. Автоматический повтор provider mutation после неоднозначного outcome запрещён.

## Безопасность

- secret values не входят в публичные request/evidence contracts; используются только ограниченные secret references там, где это уже предусмотрено 0.57;
- provider payload не становится общим execution API;
- infrastructure/network/filesystem mutation и external publication не выдаются этим release scope;
- stale Household/device/member/provider bindings отклоняются;
- durable Jobs/Audit/evidence и idempotency защищают replay/restart boundaries;
- CodeQL security-extended, repository privacy boundary и infrastructure-neutrality являются обязательными exact-candidate release gates.

## Upgrade / rollback

Поддерживаемая release boundary: официальный Public Stable 0.57.0 → 0.58.0. Exact candidate должен пройти clean packaging, checksum verification, install/upgrade, service health/restart, user-state/config/admin credential preservation и rollback/forward-recovery qualification. Candidate identity не подменяется внутри теста: `VERSION`, package metadata, runtime `__version__`, UI и deployment artifact обязаны совпадать с 0.58.0.

## Явно не заявлено

- multi-node HA / automatic failover — не заявлены как квалифицированные в 0.58.0;
- concrete provider execution — не заявлен как универсально доступный production capability без отдельно квалифицированного adapter;
- commercial launch clearance — не заявлен этим техническим релизом;
- provider-specific policy enforcement и automatic infrastructure mutation не входят в scope 0.58.0.

Эти ограничения не должны маскироваться как PASS. Пользовательский продукт при этом может быть опубликован как bounded technical Public Stable после успешной exact-candidate qualification обязательных технических gates.
